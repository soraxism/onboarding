# AIチャット・ヒントの途中離脱のCSV記録対応

詳細仕様: `2026-08-10_ai-abandonment-csv-logging-spec-changes.md`

---

## 問題点

### 1. AI利用カウンタとCSV会話ログの件数が一致しない

カウンタの加算は **AI呼び出しより前**、CSVの元ログ保存は **AI応答完了後** に行われる。
この間でエラーになるとカウンタだけ増えてCSVに残らないため、乖離は常に「カウンタ ≧ CSV」の一方向で発生する。

実測（prod）:

| | 乖離率（離脱を含む） | 乖離率（実エラーのみ） |
|---|---|---|
| AIチャット | 0.05% | 0.05% |
| **AIヒント** | **2.49%** | 0.19% |

**乖離の92%はユーザーの途中離脱が原因**で、システム異常起因は0.2%未満。
原因は両プロダクトの実装差で、AIヒントは離脱時に `GoneException` を raise して保存処理に到達しない。
AIチャットは例外を握りつぶして処理を継続するため保存に到達する。

### 2. 途中離脱が記録されていない

離脱率はチャット2.38% / ヒント2.30%で同水準に発生しているが、CSVに記録がないため
顧客も社内も「AIの回答が最後まで届いたか」を分析できない。

### 3. 付随する問題

- **AIチャット**: 離脱後も平均55.8チャンクの送信を試行し続け、無駄な処理とログが発生している
- **AIヒント**: 離脱がLambdaの未処理例外になり、Errors が **504件/30日**（エラー率6.5%）発生。アラーム未設定のため気づかれていない
- **旧チャット**（`Onboarding-AI-Server/src/functions/aiChat`）が未使用のまま残存し、共有レイヤーの変更を妨げている

---

## 対応方針

| # | 内容 |
|---|---|
| 1 | **「利用した」の定義を明文化** — プロダクトとチャット設定/ヒントウィジェットが特定でき、月間上限内であるリクエストを受け付けた時点で1回。**途中離脱も1回として計上**。preview / dev は対象外。**カウンタの実装変更はなし** |
| 2 | **AIヒントの離脱時挙動をAIチャットに寄せる** — 離脱をエラー扱いせず処理を継続し、CSVログ保存まで到達させる |
| 3 | **途中離脱をCSVに記録** — 新列「回答の到達状況」を追加（`途中離脱` / `最後まで到達` / `記録開始前` の3値） |
| 4 | **離脱後のチャンク送信を停止** — ストリーム自体は読み切り、CSVには完全な回答を残す |
| 5 | **離脱を WARNING でログ記録** — チャット・ヒント共通。Slack通知は既存チャンネルで継続（@channelメンションなし） |
| 6 | **月間上限のバッファを廃止** — 乖離が実エラー水準（0.2%未満）に収束するため。適用はリリース後 |
| 7 | **旧チャットを先に撤去** — 共有レイヤーの変更制約を外し、後続実装を簡素化する |

---

## 変更内容

| リポジトリ | 変更概要 |
|---|---|
| **Onboarding-AI-Server** | 旧チャット（`src/functions/aiChat`）を撤去／送信層で `GoneException` を raise せず戻り値で通知／離脱後の送信をスキップ／離脱ログを WARNING に／CSVログに離脱フラグを追加／離脱専用のSlack通知を新設 |
| **Onboarding-AI-API** | 離脱検知フラグを追加し以降の送信・ログを抑止／離脱ログを WARNING に（prodのログレベルを ERROR → WARNING）／CSVログに離脱フラグを追加／離脱専用のSlack通知を新設 |
| **onboarding-batch** | `ai_chat_logs` / `ai_logs` の両テーブルに `abandoned int` を末尾追加。過去データは NULL のまま維持する必要あり |
| **onboarding-manage-api** | CSV出力SQL 2ファイルに「回答の到達状況」列を追加（`abandoned` を3値に変換） |

**Athena は手動作業が必要**: `CREATE TABLE IF NOT EXISTS` は既存テーブルに効かないため、
`ALTER TABLE ... ADD COLUMNS (abandoned int)` を **dev / prod 両環境の両テーブル**に実行する。

## リリース順序（この順序は必須）

| フェーズ | 対象 | 逆順にできない理由 |
|---|---|---|
| **0** | 旧チャット撤去（AI-Server） | 先に撤去しないと共有レイヤー変更で旧チャットの同時修正が必要になる |
| **1** | onboarding-batch ＋ Athena | アプリを先に出すとバッチが未知の列を落とし、**その期間の離脱情報は復旧不可** |
| **2** | AI-API / AI-Server | — |
| **3** | onboarding-manage-api | 列がない状態でSQLが参照すると Athena がエラーになり、**顧客のCSVダウンロードが失敗する** |
| **4** | 事後確認・バッファ廃止 | 実データが揃わないと確認できない |

フェーズ0と1は対象リポジトリが異なるため並行可能。

**最大のリスクはフェーズ0。** AIヒントのWebSocket接続の `$connect` / `$disconnect` を現在は旧チャットのLambdaが処理しており、
撤去によって統合先が切り替わる。**必ず dev で先に検証し、prod はアクセスの少ない時間帯に実施する。**

## 顧客への影響

| 影響 | 内容 | 対応 |
|---|---|---|
| CSVに新列が1つ増える | 「回答の到達状況」。リリース前の期間は「記録開始前」と表示される | — |
| **AIヒントのCSVレコード数が約2.3%増える** | 離脱分が新たに記録されるため。リリース日を境に増加 | 事前アナウンスは行わない |

## 期待効果

| 項目 | 改修前 | 改修後 |
|---|---|---|
| 乖離率（AIヒント） | 2.49% | **0.19%**（実エラーのみ） |

| 途中離脱の可視化 | 不可 | CSV・Athenaで集計可能 |
