# イントロのチェックマークが付くタイミングを管理画面で選択できるようにする

詳細ドキュメント:
- 現状調査: [docs/ONBS-1991/2026-09-07_current-behavior-survey.md](./2026-09-07_current-behavior-survey.md)
- 設計案（管理画面UI / データ / 実装方針）: [docs/ONBS-1991/2026-09-07_admin-ui-and-data-design.md](./2026-09-07_admin-ui-and-data-design.md)

---

## 概要

イントロ（ゴール一覧）のチェックマークは、現在**ゴールを開いて1ステップ表示した時点**で付く。
最後まで進めずに閉じてもチェックが付いたままになるため、
「どのゴールをやり切ったか」がエンドユーザーに伝わらない。

チェックマークが付くタイミングを、**「ゴールを開いたとき」/「最後のステップを表示したとき」**の
2択で管理画面から選択できるようにする。

---

## 問題点

### 1. チェックマークが「開始時」に付く

イントロのチェック判定が `完了ゴール ∪ 表示済みゴール` の論理和になっている
（`onboarding-web/src/onboarding-init.ts:653-673`）。
`表示済みゴール`（`onb_display_goals_{tourID}`）は 1 ステップ表示した時点で記録されるため
（`src/stands.onbd.ts:859-870`）、開いただけでチェックが付く。

### 2. 「完了」の定義が3系統に分かれている

| 対象 | 「完了」の判定 |
|---|---|
| **レポート（完了UU）** | **最終ステップの表示**（`step_index == total_steps`） |
| イントロのチェックマーク | ゴールを開いた（1ステップ目の表示） |
| LS `onb_complete_goals_` / 自動表示条件「完了済み」/ 公開API | 終了ボタン押下（`finish`） |

レポート集計は `onboarding-batch/src/report_goal_details/functions/aggregate.py:316-317` で
`step_index == total_steps` の表示ログを完了として数えており、
**`completed` トラッキングイベントは `onboarding-batch` のどの集計でも使われていない**。

→ 本対応（チェックマークを最終ステップ表示基準にできるようにする）は、
**イントロの見た目をレポートの完了定義に一致させる**変更にあたる。レポートの数値は変わらない。

### 3. 顧客ごとの個別カスタムJSで同じ課題が個別対応されている

`src/customize/prod/65`（独自 finish でチェック制御）、`prod/7738`・`7740`・`13`・`722`・`957`・`982`・`999`
（表示済みゴールを「確認済み/未確認」と自前描画）など。
今回は標準機能に寄せず、**標準実装がこれらを壊さないこと**を確認済み（調査ドキュメント §8）。

## 対応方針

管理画面のツアー「表示スタイル設定」→「イントロ」タブ →「チェックマーク」セクションに
**チェックマークを付けるタイミング**の選択肢を追加する（既にチェックマークの背景色を設定する場所）。
**エディタ拡張機能にも同じ設定UIを実装する**（イントロは両方で編集できるため）。

| 値 | ラベル | 付くタイミング |
|---|---|---|
| `goal_started`（**既定**・現行挙動） | ゴールの表示（いずれかのステップが表示） | 1ステップ目の表示時 |
| `last_step_displayed` | ゴールの完了（最後のステップが表示） | 最終ステップの表示時（レポートの完了集計と同一基準） |

- 保存先は `steps_json_src.settings.styles.intro.checkmarkTiming`（ツアー単位）
  → 管理画面は既存の WebSocket `tourStylesUpdate` に相乗りでき、**配信APIの変更は不要**
- 未設定のツアーは `goal_started` として扱い、既存ツアーの見え方を変えない
- ランチャーの未完了ゴール数も同じ基準で数えるため設定に連動して変わるが、**UIには注記しない**（決定事項を参照）

### エンドユーザー側（onboarding-web）の変更点

1. `setLauncher()` のチェック判定を設定値で分岐（`last_step_displayed` では `完了 ∪ 最終ステップ表示済み`）
2. 「最終ステップを表示したゴールID」を**新規LSキー** `onb_last_step_displayed_goals_{tourID}` に記録
   - `onb_complete_goals_` の書き込みタイミングは変えない
     → 自動表示条件「完了済み」・公開API `getIncompleteGoalIds()`・
       `prod/28` のゴール出し分け（完了済み判定でゴールを切り替える）を不変に保つ
   - 判定は `step_data.index === goal.steps.length` でレポートと同一基準
   - **設定値に関わらず常に記録する**（後から設定を切り替えたときの引き継ぎ精度のため）
3. 進行中にチェックを反映するため、イントロDOMのクラスを直接差し替え
   （`modalTemplate` は文字列で、再生成しても表示中の画面には反映されないため）。
   **設定が `last_step_displayed` のときだけ実行**し、既定値の顧客では新しいDOM操作を走らせない

## 設定切替時のチェックマークの引き継ぎ（仕様として要周知）

過去に「最終ステップを表示したが終了ボタンを押していない」状態は**LSに記録がなく、遡って復元できない**
（`iGuider_data-{tourID}` は復元用で `finish` / `abort` 時に削除されるため使えない）。

| 過去のユーザー状態 | 現行の見た目 | 「最後のステップを表示したとき」に切替後 |
|---|---|---|
| 終了ボタンまで押した | ✓ | `onb_complete_goals_` に残っているので **✓ 維持** |
| 最終ステップを表示 → × で閉じた | ✓ | 記録がないため **✗ 外れる** |
| 途中まで見て閉じた | ✓ | ✗（設定変更の意図どおり） |
| 未着手 | ✗ | ✗ |

- 判定を `完了 ∪ 最終ステップ表示済み` の論理和にすることで、**過去に完了したゴールのチェックは維持される**
  （論理和にしないと完了済みのチェックまで外れる）
- リリース時点から新キーの記録を始めるため、リリース〜設定変更までに到達したゴールは引き継がれる
- 「ゴールを開いたとき」へ戻す場合は `onb_display_goals_` を記録し続けているため**いつでも戻せる**
- 維持されない例外は、ブラウザのデータ削除 / シークレットウィンドウ / 別端末・別オリジン /
  第三者スクリプトによる `localStorage.clear()` / プレビュー起動・停止時のリセット。
  いずれも **LS 自体が失われるケースで現行実装でも同じ**（今回の変更で新たに増える例外はない）
- 2行目のケースを許容しない場合（切替時に `display_goals` を引き継ぐ移行処理を入れる場合）は、
  「開いただけのゴール」もチェックが残るため**設定変更の効果が既存ユーザーに出ない**。
  詳細は調査ドキュメント §7

### 併せて直す必要がある既存の問題（設定消失）

エディタ拡張機能のチェック色変更 API（`api/rest-ext-editor/functions/tours-tour-id-intro-style/method_put.py:53`）は
`settings.styles.intro` を**丸ごと置換**しており、拡張機能が送るのは `checkmark` のみ。
このままでは**管理画面で設定したタイミングが、拡張機能でチェック色を変えた瞬間に消える**。

- 同APIを部分更新（受け取ったキーのみ上書き）に修正する。cover 更新APIは既に部分更新であり、そちらに揃える
- 併せて拡張機能側の送信ペイロードにも両キーを含める

## 決定事項（2026-09-08）

- 選択肢は**2択**（終了ボタン押下は選択肢に含めない）
- 変更範囲は**イントロのチェックマークのみ**（レポート・自動表示条件・公開APIは不変）
- 既定値は**「ゴールを開いたとき」**（現行挙動）
- ゴール連結ありゴールで「まだ次へ続くのに完了になる」挙動は**許容する**
- 顧客個別カスタムは**標準機能に寄せない**（標準実装が壊さないことは確認済み）
- 管理画面 / エディタ拡張機能 / onboarding-web は**同時リリース**
- 設定切替時に「最終ステップを表示したが終了ボタンを押していない」ユーザーのチェックが外れることは
  **許容する**（移行処理は入れない）。終了ボタンを押したゴールは論理和判定で維持される
- 旧実装 `onboarding-web/src/js/` 側にも**同時反映する**
- 新規ツアーのテンプレートに既定値を**入れる**
- 管理画面の「デフォルトに戻す」は**背景色だけを戻す現状の挙動を維持する**（タイミングは戻さない）
- 入力部品は**カード型ラジオの縦並び**（`UiRadio` に `componentType="cardVertical"` を追加）。
  選択肢の文言が長くフォーム欄が狭いため、セレクト・横並びラジオ・横並びカードでは収まらなかった
- バッジ（未完了ゴール数）が連動する旨は**UIに書かない**（未完了ゴール数の表示自体があまり使われておらず、
  設定画面の注記としてはノイズになるため。仕様としては連動する）
