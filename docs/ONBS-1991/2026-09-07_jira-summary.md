# イントロのチェックマークが付くタイミングを管理画面で選択できるようにする

詳細ドキュメント:
- 現状調査: [docs/ONBS-1991/2026-09-07_current-behavior-survey.md](./2026-09-07_current-behavior-survey.md)
- 設計案（管理画面UI / データ / 実装方針）: [docs/ONBS-1991/2026-09-07_admin-ui-and-data-design.md](./2026-09-07_admin-ui-and-data-design.md)

---

## 概要

イントロ（ゴール一覧）のチェックマークは、現在**ゴールを開いて1ステップ表示した時点**で付く。
最後まで進めずに閉じてもチェックが付いたままになるため、
「どのゴールをやり切ったか」がエンドユーザーに伝わらない。

チェックマークが付くタイミングを管理画面から選択できるようにする。

---

## 問題点

1. **チェックマークが「開始時」に付く**
   イントロのチェック判定が `完了ゴール ∪ 表示済みゴール` の論理和になっている
   （`onboarding-web/src/onboarding-init.ts:653-673`）。
   `表示済みゴール`（`onb_display_goals_{tourID}`）は 1 ステップ表示した時点で記録されるため
   （`src/stands.onbd.ts:859-870`）、開いただけでチェックが付く。

2. **「完了」の定義が機能ごとにズレている**
   LocalStorage 上は「完了（`onb_complete_goals_`、終了ボタン押下時）」と
   「表示済み（`onb_display_goals_`）」が別キーで正しく分離されており、
   自動表示条件（完了済み / 未完了 / 表示済み / 未表示）や公開API `getIncompleteGoalIds()` は
   「完了」のみを見ている。**イントロのチェックマークだけが論理和**という状態。

3. **顧客ごとの個別カスタムJSで同じ課題が個別対応されている**
   `src/customize/prod/65`（独自 finish でチェック制御）、`prod/7738`・`7740`・`13`
   （表示済みゴールを「確認済み/未確認」と自前描画）など。標準機能化すれば個別対応を減らせる。

---

## 対応方針

管理画面のツアー「表示スタイル設定」→「イントロ」タブ →「チェックマーク」セクションに
**チェックマークを付けるタイミング**の選択肢を追加する（既にチェックマークの背景色を設定する場所）。

| 値 | ラベル案 | 付くタイミング |
|---|---|---|
| `goal_started`（既定・現行挙動） | ゴールを開いたとき | 1ステップ目の表示時 |
| `last_step_displayed` | 最後のステップを表示したとき | 最終ステップの表示時 |
| `goal_finished` | ゴールを完了したとき | 「終了」ボタン押下時 |

- 保存先は `steps_json_src.settings.styles.intro.checkmarkTiming`（ツアー単位）
  → 管理画面は既存の WebSocket `tourStylesUpdate` に相乗りでき、**配信APIの変更は不要**
- **エディタ拡張機能側にも同じ設定UIを実装する**（イントロは両方で編集できるため）
- 未設定のツアーは `goal_started` として扱い、既存ツアーの見え方を変えない
- ランチャーの未完了バッジ数も同じ基準で数えるため、設定に連動して変わる（仕様として明示する）

### エンドユーザー側（onboarding-web）の変更点

1. `setLauncher()` のチェック判定を設定値で分岐
2. `last_step_displayed` 用に「最終ステップを表示したゴールID」を新規LSキーで記録
   （`onb_complete_goals_` に混ぜない = レポート・自動表示条件・公開APIに影響を出さない）
3. 進行中にチェックを反映するため、イントロDOMのクラスを直接差し替え
   （`modalTemplate` は文字列で、再生成しても表示中の画面には反映されないため）

## 影響範囲

| リポジトリ | 影響 |
|---|---|
| `onboarding-web` | チェック判定・最終ステップ記録・イントロDOM更新・LSキー追加・型・ユニットテスト・仕様書 |
| `onboarding-manage-web` | 表示スタイル設定モーダル（イントロタブ）にラジオ追加、補足文の修正 |
| `Onboarding-Editor-Extension` | **設定UIの実装が必須**。ツアーのイントロは拡張機能でも編集でき、チェックマークの色設定が既に存在する（ゴール一覧選択時のインラインメニュー）。UI・emit中継・composable・型・ダミー・テストで計8ファイル程度 |
| `onboarding-manage-api` | 管理画面用WS（`tourStylesUpdate`）は変更なし。**拡張機能用の `PUT tours/{id}/intro-style` は修正が必須**（下記） |
| `onboarding-api` | 変更なし（`settings` をそのまま配信するため） |
| `onboarding-e2e-test` | `tests/common/intro/goalDisplayed.js` が「開いて中断 → チェックが付く」を検証している。既定値を現行維持にすればそのまま通る。「終了時」シナリオを追加 |

### 併せて直す必要がある既存の問題（設定消失）

エディタ拡張機能のチェック色変更 API（`api/rest-ext-editor/functions/tours-tour-id-intro-style/method_put.py:53`）は
`settings.styles.intro` を**丸ごと置換**しており、拡張機能が送るのは `checkmark` のみ。
このままでは**管理画面で設定したタイミングが、拡張機能でチェック色を変えた瞬間に消える**。

- 同APIを部分更新（受け取ったキーのみ上書き）に修正する。cover 更新APIは既に部分更新であり、そちらに揃える
- 併せて拡張機能側の送信ペイロードにも両キーを含める
- 管理画面のみ先行リリースすると設定消失が起きるため、**このAPI修正は管理画面リリースと同時に入れる**

### 注意点

- 公開API `STANDSMotion.setCheckedGoalIds()`（`onb_checked_goals_ids_`）を使っている顧客では、
  そちらが最優先されるため新設定は効かない
- 「完了」という語をUIに出すとレポートの完了率（`completed` トラッキング = 終了ボタン押下で集計）と
  混同されるため、ラベルは「チェックマークを付けるタイミング」に寄せる
- ゴール連結が設定されたゴールでは、最終ステップでも「次へ」で連結先に進むため、
  `last_step_displayed` では「続きがあるのにチェックが付く」状態になる（許容するか要判断）

## 確認事項

1. 選択肢は2択（開始時 / 終了時）か3択（開始時 / 最終ステップ表示時 / 完了時）か
2. 要望の「ゴール完了」は**イントロのチェックマークだけ**か、レポートの完了数も含むか
   （後者はレポートの完了率が変動する）
3. 既定値は現行維持（ゴールを開いたとき）でよいか
4. ゴール連結ありゴールで「最終ステップ表示＝チェック」を許容するか
5. 顧客個別カスタム（`prod/65`・`7738`・`7740`・`13` 等）を標準機能に寄せるか
6. 管理画面とエディタ拡張機能を同時リリースするか（管理画面のみ先行なら、少なくとも
   `intro-style` APIの部分更新化は同時に入れる）
