# 個人情報漏えい 机上訓練 ファシリテーター用進行台本

**シナリオ**: 取引先から「送付資料に別社の情報が混在している」と指摘される（誤抽出・誤送付）
**所要時間**: 60分（オプション込み75分）
**形式**: 机上訓練（ロールプレイ＋ディスカッション）。実システムには一切触れない

> **取扱注意**: この文書はファシリテーターのみが持つ。参加者には訓練終了まで開示しない。
> 終了後は `2026-09-07_incident-drill-handout.md` を配布する。

---

## 0. この訓練の設計思想

**成果物は「うまくできたかの評価」ではなく「決められなかったことのリスト」。**

当社にはまだ対応フローが存在せず、CSIRT相当の組織もない。したがってこの訓練は
「フロー通りに動けるか」のテストではなく、**フローに何を書くべきかを洗い出す要件定義**である。

参加者が詰まるほど成功。ファシリテーターは正解を配らず、詰まった箇所を記録係に確実に拾わせる。

**特に炙り出したい5点**

| # | 検証したいこと | なぜ |
|---|---|---|
| 1 | 第一報が責任者に届くまでの経路と時間 | 一報は営業/CSに来る。エンジニアチームには直接来ない |
| 2 | 「疑い」段階でエスカレーションできるか | 確証を待つと初動が数日遅れる |
| 3 | 「知った時」の時刻を記録する意識 | 法定報告期限の起点。曖昧だと後で詰む |
| 4 | 判断者が誰か即答できるか | CSIRTがない現状で最大の空白地帯 |
| 5 | 証跡保全の指示が出るか | 調査のためにログを触って上書きするのが典型的事故 |

## 3. 進行台本

### オープニング（0:00 - 0:05）

読み上げ推奨:

> 「今日は1時間、個人情報が漏えいしたときの机上訓練をやります。
> 実際のシステムには触りません。すべて架空の設定です。
>
> 最初に2つだけお伝えします。
>
> **1つ目。この訓練では、誰かのミスを責めません。実際の事故でも同じルールにします。
> 隠されるほうが会社にとって危険だからです。**
>
> **2つ目。今日のゴールは"うまく対応できること"ではありません。
> "決められなかったこと"を見つけることです。詰まったら、詰まったと言ってください。
> それが今日いちばん価値のあるアウトプットです。**
>
> 役割をお伝えします。（役割を読み上げる）
> では始めます。」

> **理想**: 「無罰」の宣言は、ファシリテーターではなく**ISMS責任者本人に言ってもらう**。
> 誤送信インシデントの検知速度は、当事者が申告する気になるかどうかでほぼ決まる。
> 責任者の口から出るかどうかで効き方が変わる。

---

### インジェクト① 第一報（0:05 - 0:15）

**投入方法**: 訓練用Slackチャンネルに、ファシリテーターが「A社 田中さん」として一報を投稿する。
一次受け役に対して「今、あなたのSlackにこれが届きました」と伝える。

**投げる問い**（一次受け役に名指しで振る）

1. 今この瞬間、誰に、何分以内に連絡しますか
2. これは「インシデント」ですか、「問い合わせ」ですか
3. A社に今すぐ返信するとしたら、何と書きますか
4. この時点で記録しておくべきことは何ですか

**詰まったときの誘導セリフ**

| 状況 | セリフ |
|---|---|
| 全員が黙る | 「今、これは誰の仕事ですか？」 |
| 「確認します」で止まる | 「"確認します"と返しました。では社内では、誰に何を伝えますか」 |
| 温度が低い | 「これが個人情報の漏えいだったとしたら、まずいのはどこですか」 |
| **即座に「削除してもらう」と答える** | 「わかりました、A社は削除しました。……では、何が混ざっていたか、これから調べられますか？」 |
| 責任者に上げない | 「A社さんは返信を待っています。30分以内に何か返すとして、その内容は誰が承認しますか」 |

**記録係に拾わせるポイント**
- 第一報の受信時刻から、責任者に届くまでの**経過時間**（ホワイトボードに書く）
- 「疑い」の段階で上げたか、確証を取ってから上げたか

> **隠れた論点（言わない）**: 「削除してください」と即答すると証拠が消える。
> 正解に近いのは「削除せず、これ以上共有しないでお待ちください」。高確率で引っかかる。

### インジェクト② 原因が見えてくる（0:15 - 0:26）

**読み上げ**:

> 「当事者エンジニアが確認しました。
> AthenaでA社向けの操作ログを抽出した際、**テナントIDの絞り込み条件が意図通りに効いていませんでした**。
> CSVは約48,000行。他テナントのデータが含まれています。
> **含まれる人数は、現在集計中です。**」

**投げる問い**

1. 誰が調査しますか。当事者本人にやらせますか
2. 調査のために本番環境を触ります。何に気をつけますか
3. 保全すべき証跡は何ですか
4. 同じ手順で過去にも渡していないか、どう確認しますか

**詰まったときの誘導セリフ**

| 状況 | セリフ |
|---|---|
| 当事者が一人で抱える | 「当事者ご本人が調査するんですね。それで問題ないですか？」 |
| 証跡の話が出ない | 「1週間後に"根拠を出してください"と言われます。今、何が残っていますか」 |
| 証跡を列挙できない | 「クエリ履歴、送ったCSVの現物、Slackのログ……他には？」 |
| **過去分に思い至らない** | 「今回のクエリ、初めて書いたものですか？」 |
| 調査手順が雑 | 「Athenaを叩きます。その操作自体もログに残りますが、大丈夫ですか」 |
| 技術的な原因究明に流れて長引く | 「原因は後で分かります。**今**、A社に何と返しますか」 |

**記録係に拾わせるポイント**
- 「過去分も確認する」に到達したか、したなら何分かかったか
- 証跡保全の指示が誰から出たか（出なければそれを記録）

### インジェクト③ 規模と中身が判明（0:26 - 0:41）★最重要

**読み上げ**:

> 「集計が終わりました。
>
> **他テナント3社分、ユニークユーザー 1,240名。**
>
> 含まれていた項目は、
> ユーザーID / 氏名 / メールアドレス / 所属部署 / IPアドレス / 操作日時 / 閲覧したガイド名 です。」

**投げる問い**

1. これは個人情報保護法上の報告対象ですか
2. 報告するのは誰ですか。当社ですか、データの持ち主である3社ですか
3. 1,240名の本人に通知しますか。連絡先は持っていますが、勝手に連絡していいですか
4. 影響を受けた3社に、いつ・誰が・何を伝えますか

**進め方**: 問い1で**挙手させる**。「報告義務があると思う人？ ないと思う人？ 分からない人？」
割れることに意味がある。割れた事実を記録係に書かせる。

**詰まったときの誘導セリフ**

| 状況 | セリフ |
|---|---|
| 「48,000件の漏えい」と言う | 「48,000ですか？ その数字はどこから出しましたか」 |
| 件数の数え方が曖昧 | 「法律が数えるのは行数ですか、人数ですか」 |
| 報告義務の判断に進まない | 「報告するかしないか、今日決めないといけません。決めるのは誰ですか」 |
| **当社か3社かの整理が出ない** | 「このログの個人データ、当社のものですか？ 3社からお預かりしているものですか？」 |
| さらに詰まったら | 「契約書、今すぐ出せますか。どこにありますか」 |
| 本人通知を軽く扱う | 「1,240名に当社から直接メールしますか。それは誰の判断で、文面は誰が承認しますか」 |
| 「1,000人以下なら何もしなくていい」と言う | 「法律上の義務がないとして、契約上の義務はどうですか」 |
| 3社への連絡が後回しになる | 「3社さんが他のルートでこれを知ったら、どうなりますか」 |

**記録係に拾わせるポイント（この15分が本番）**
- 報告義務の判断が**割れたか**、割れたまま終わったか
- 「委託か自社取得か」の契約上の整理を**即答できたか**
- 参照すべき契約書の在り処を誰か知っていたか
- 相談先（法務・顧問弁護士）の名前が出たか

> **隠れた論点（言わない）**
> - 件数は行数ではなく**本人の数**。48,000行ではなく1,240名
> - 1,000人超は報告対象になり得る（1,240名）
> - **報告主体は契約上の立て付けで変わる**。当社が3社から個人データの取扱いの委託を
>   受けている立場なら、委託元である3社への通知で当社の報告義務は免除され得る。
>   逆に当社が自ら取得した個人情報という整理なら、当社が報告主体
> - **この整理が社内で即答できないこと自体が、今日いちばんの発見**

### インジェクト④ 二次拡散（0:41 - 0:47）

**投入方法**: 訓練用Slackチャンネルに「A社 田中さん」から続報を投稿。

**投げる問い**

1. A社に何を依頼しますか。口頭確認で足りますか、書面が要りますか
2. 「削除しました」を、どうやって「確認した」と言える状態にしますか
3. 結局、「知った時」の起点は何時何分ですか
4. これが金曜19時に起きていたら、同じように動けましたか

**詰まったときの誘導セリフ**

| 状況 | セリフ |
|---|---|
| 「削除確認して終わり」 | 「"削除しました"と言われました。信じますか」 |
| 記録の話が出ない | 「1ヶ月後に監査で聞かれます。"削除を確認した"根拠は何ですか」 |
| 起点が曖昧 | （ホワイトボードの時系列を指して）「では改めて。法律上の"知った時"は、この中のどれですか」 |
| 全員が平日昼の前提でいる | 「今日が金曜の19時だったとしたら、ここまで同じように動けましたか」 |

**記録係に拾わせるポイント**
- 「知った時」について**参加者間で答えが割れたか**
- 夜間・休日の連絡経路が存在しないことに気づいたか

---

### インジェクト⑤ 公表判断（オプション / 75分版のみ）

**投入方法**: 訓練用Slackに、影響を受けた別テナントB社から問い合わせを投稿。

**投げる問い**
1. 公表しますか。判断するのは誰ですか
2. 公表するとして、いつ、どこに、何を書きますか
3. 記者から電話が来たら、誰が出ますか

**誘導セリフ**
- 「今、社外に出す文章を書けるのは誰ですか」
- 「B社さんは、自社のユーザーに説明する義務があります。当社は何を提供しますか」

### 振り返り（0:47 - 0:58）

**進め方**: 評価も採点もしない。参加者全員に振り返りシートの3ブロックを**先に個人で3分書かせてから**、
ホワイトボードに集約する。いきなり全体議論にすると声の大きい人の意見だけが残る。

**読み上げ**:

> 「お疲れさまでした。ここからが本番です。
> シートを配りますので、まず3分間、一人で書いてください。
>
> 埋めるのは3つだけです。
> **A. 決められなかったこと**
> **B. 誰に聞けば分かるか、分からなかったこと**
> **C. 存在しなかったもの**
>
> "こうすればよかった"は書かなくて大丈夫です。困ったことだけ書いてください。」

3分後、A → B → C の順に一人ずつ読み上げさせ、記録係がホワイトボードに書き出す。
**重複は消さない**。複数人が挙げた項目は優先度が高い。

**ファシリテーターが最後に必ず確認する項目**（出ていなければ問いかける）

- [ ] 一次受けから責任者までのエスカレーション先は決まっているか
- [ ] 「疑い」で上げていいという合意はあるか
- [ ] 委託／自社取得の契約上の整理は、誰が答えられるか
- [ ] 夜間・休日の連絡経路はあるか
- [ ] 顧客への通知文テンプレートはあるか
- [ ] Athenaからの手動抽出に、テナント絞り込みのレビュー工程はあるか

> 最後の項目は技術的な再発防止策として最重要。ここは必ず議題に乗せる。

---

### クロージング（0:58 - 1:00）

> 「今日出た"決められなかったこと"のリストが、そのまま対応フローの目次になります。
> 次回までにドラフトを作って、また同じシナリオで動作確認します。
>
> 最後にもう一度だけ。**実際に何かやってしまったときは、隠さず、すぐ言ってください。
> 早く言うほど被害が小さくなります。それだけです。**
>
> 資料を配ります。今日の論点の解説が入っているので、後で目を通してください。」

## 4. ファシリテーターの禁止事項

| 禁止 | 代わりにやること |
|---|---|
| 正解を言う | 「そう動いた場合、次に何が起きますか？」と返す |
| 「それは違います」と言う | 「なるほど。その前提だと、あとで困ることはありますか？」 |
| 沈黙を埋める | **10秒待つ**。日本語の会議では10秒はかなり長いが、待つと誰かが話す |
| 当事者エンジニア役を実際に責める | 責めそうな空気になったら「今日は無罰ルールでしたね」と一言入れる |
| 参加者の議論を要約して先に進める | 記録係に書かせてから進める |
| 時間が押して③を削る | 削るのは①か④ |

## 5. よくある展開と対処

| 展開 | 対処 |
|---|---|
| 全員が黙り込む | 名指しで一次受け役に振る。「〇〇さんのSlackに来ています。どうしますか」 |
| 技術的な原因調査に議論が全振りされる | 「原因は後で分かります。今A社に何と返しますか」で対外対応に戻す |
| 責任者が細部まで指示し、他が受け身になる | 「責任者は今から3分間だけ席を外した設定にします。この3分で何を進めますか」 |
| 「うちは委託先だから関係ない」で終わらせる | 「では、3社さんには誰がいつ伝えますか」でインジェクト③の契約論点に戻す |
| 「法務に聞けばいい」で思考停止 | 「法務は何時に捕まりますか。金曜19時でも？」 |
| 想定より早く終わってしまう | インジェクト⑤を投入。それでも余ればフローのドラフト作成に時間を回す |
| 感情的になる参加者が出る | 一度休憩を挟む。訓練であることを再度明示する |

## 6. 訓練後の宿題（ファシリテーター）

1. 振り返りシートの A / B / C を統合し、**対応フローの目次**に変換する
2. 各項目に責任者と期限を割り当てる
3. 技術面の再発防止（Athena抽出のレビュー工程・テナント絞り込みの仕組み化）はエンジニアチームのタスクとして別途起票
4. フローのドラフトができたら、**同じシナリオでもう一度実施**して動作確認する
