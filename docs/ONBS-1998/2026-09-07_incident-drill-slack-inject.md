# 個人情報漏えい 机上訓練 Slack投入用テキスト

**用途**: 机上訓練のインジェクト（情報投入）を、実際のクライアント連絡と同じSlackで行うための文面集
**投稿者**: ファシリテーターが「取引先A社 田中さん」役として投稿する
**前提**: 全員リモート。連携はSlack、音声はSlackハドル / Google Meet

---

## ⚠️ 実施前に必ず読むこと

| # | 厳守事項 |
|---|---|
| 1 | **実際のクライアントとのSlackチャンネル（Slack Connect含む）には絶対に投稿しない。** 誤爆すると本物のインシデントになります |
| 2 | 訓練専用チャンネルを新規作成する。**チャンネルトピックに「【訓練用】ONBS-1998 机上訓練専用」と明記する** |
| 3 | ISMS責任者にだけは事前共有しておく（暴走時に止められるようにするため） |
| 4 | **訓練は必ずその日のうちに終了させ、ネタバラシまで行う。** 持ち帰らせない |
| 5 | 参加者が本物のクライアントや社外に連絡しようとしたら、**即座に訓練であることを明かして止める** |

---

## チャンネル構成

**片方だけを用意する。** 社内対応用チャンネルを参加者が自分で立てるかが観測点になる。

| チャンネル | 用意するか | 役割 |
|---|---|---|
| `#drill-onbs-1998-a社` | **ファシリテーターが作る** | A社との共有チャンネル想定。田中さん役として投稿する場。参加者全員を招待 |
| 社内対応用チャンネル | **あえて用意しない** | 参加者が作るかを観測する。作らなければそれ自体が発見 |

- Google Meet のリンクは `#drill-onbs-1998-a社` に投稿しておく
- **A社との共有チャンネルで参加者が社内調整を始めても止めない。** 実際なら顧客に全部見えていた、という材料になる

### 抜き打ち度の選択

| レベル | やり方 | 向いている場面 |
|---|---|---|
| **推奨** | 事前に「今日1時間、訓練をやります」と伝えたうえで、開始時にSlackへ投稿 | 初回。安全で、かつ十分に緊張感が出る |
| 完全抜き打ち | 予告なしにSlackへ投稿し、反応を見る | 2回目以降。責任者への事前共有と、90分での強制終了ルールを必ずセットにする |

初回は**推奨レベル**で十分です。完全抜き打ちは、フローが整備されてからの実力テストに取っておいてください。

```

・テナントIDの絞り込み条件が意図通りに効いていなかったことに、まだ気づいていません

訓練が始まったら、この役として自然に振る舞ってください。
聞かれていないことを先回りして言う必要はありません。
無罰ルールなので、責められることはありません。
```

## インジェクト② 原因（社内向け・参考）

**投稿先**: 参加者が社内対応チャンネルを作っていればそこへ。なければMeetで読み上げる。

> 参加者が当事者エンジニア役にヒアリングしていない場合、**この情報を渡さずに待つ**。

```
【調査中間報告】
AthenaでA社向けの操作ログを抽出した際、テナントIDの絞り込み条件が
意図通りに効いていませんでした。

CSVは約48,000行。他テナントのデータが含まれています。
含まれる人数は現在集計中です。
```

## インジェクト③ 集計結果と投票（社内向け）

**投稿先**: 社内対応チャンネル、なければ `#drill-onbs-1998-a社`
**投稿タイミング**: 0:26

> **この情報は必ず文字で投稿する。** 後で数字を参照するため。

```
【集計結果】
他テナント3社分、ユニークユーザー 1,240名

含まれていた項目:
ユーザーID / 氏名 / メールアドレス / 所属部署 / IPアドレス / 操作日時 / 閲覧したガイド名
```

続けて投票を投稿し、`:one:` `:two:` `:three:` のリアクションを付けておく。

```
【投票】これは個人情報保護法上の報告対象だと思いますか

:one: 報告対象だと思う
:two: 報告対象ではないと思う
:three: 判断できない

※他の人のリアクションを見る前に、まず自分の考えで押してください
```

> 全員が押したら、**結果のスクリーンショットを記録係に保存させる。**
> Slackのリアクションは後から変えられるため、その場で撮る。

## ファシリテーター用 応答パターン集

訓練中、参加者が「A社」に返信してきたときの応答例です。
**参加者の判断の甘さが、そのまま不利な展開として返ってくる**ように設計しています。

| 参加者の返信 | A社役の応答 | 狙い |
|---|---|---|
| 「すぐ削除していただけますか」 | 「承知しました、削除しました。（少し置いて）……あ、もう手元にファイルは残っていません」 | 証拠が消えたことに気づかせる |
| 「削除せずお待ちください」 | 「承知しました。こちらで保管しておきます」 | 正しい判断。そのまま進める |
| **「Slackのファイルも消してください」** | 「消しました。Slackの履歴からも消えています」 | **Slack上の証跡も消えることに気づかせる** |
| 「確認しますのでお待ちください」（時間の言及なし） | 「いつ頃までにご回答いただけますでしょうか。弊社でも社内報告が必要でして」 | 期限のコミットを迫る |
| 「調査中です」だけで30分放置 | 「その後いかがでしょうか。弊社の情報システム部から状況確認を求められております」 | 中間報告の必要性に気づかせる |
| 「何件くらい混ざっていましたか」と聞かれる | 「弊社では正確には分かりません。ざっと見ただけで数十件は目に入りました」 | 相手任せにできないことを示す |
| 「社外に共有していませんか」 | （インジェクト④を前倒しで投入してよい）「実は共有フォルダに置いてしまっていて……」 | 良い質問には情報で報いる |
| 「削除証明書をいただけますか」 | 「どういった形式で出せばよいでしょうか。書式をいただければ対応します」 | 書式がないことに気づかせる |
| **「一度お電話でお話しできますか」** | 「はい、大丈夫です。ただ、後で経緯を確認したいので**記録は残していただけますか**」 | 音声で決めたことを書き戻す必要性に気づかせる |
| 謝罪だけで具体的な次アクションがない | 「恐れ入りますが、弊社としてはいつまでに何をご報告いただけるか知りたいのですが」 | 対外コミュニケーションの型がないことを露呈させる |
| 「弊社の個人情報保護管理者から改めてご連絡します」 | 「承知しました。お待ちしております」 | 正しい判断。そのまま進める |

### 参加者がこのチャンネルで社内調整を始めたら

**止めないでください。** 記録して、振り返りで扱います。

実際のSlack Connectでは顧客に全部見えているため、
**「今日、社内の議論が何回A社さんに見えていたか」を数えて振り返りで示す**のが最も効きます。

### 参加者が本物のクライアントに連絡しようとしたら

**即座に訓練であることを明かして止めてください。**

```
ストップします。これは訓練です。実際の連絡はしないでください。
——今、実際に連絡しようとしたという判断そのものが、
振り返りで扱うべき重要なポイントです。メモしておいてください。
```

止めたこと自体を責めず、**「その判断は自然だった。だからこそフローが必要」**という文脈で扱います。

## 訓練終了時のネタバラシ文面

**投稿先**: `#drill-onbs-1998-a社`（および参加者が作った社内対応チャンネル）

```
【訓練終了】

お疲れさまでした。本日のやり取りはすべて机上訓練であり、
実際のインシデントは発生していません。
「A社の田中」「B社の佐藤」は訓練用の架空の担当者です。

実在のクライアントとは一切関係ありません。
このチャンネルの内容は社外に共有しないでください。

今日出てきた「決められなかったこと」を、これから対応フローに変換していきます。
ご協力ありがとうございました。
```

### 参加していないメンバーへの周知（必要な場合）

訓練用チャンネルが目に入る可能性のあるメンバーがいる場合、開始前に全体チャンネルへ投稿します。

```
本日 ○:○○〜○:○○ で、個人情報漏えいの机上訓練を実施します。

#drill-onbs-1998-a社 で訓練用のやり取りが流れますが、すべて架空の設定です。
実際のインシデントではありませんので、ご安心ください。

訓練中、参加メンバーが新しいチャンネルを作ったりハドルを立てたりすることがありますが、
これも訓練の一部です。
```
