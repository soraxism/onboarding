### §1 補足: 「デフォルトに戻す」は色だけを戻す（決定事項・2026-09-14）

CodeRabbit のレビューで「タイミングも戻すべき」と指摘され一度そう変更したが、
**実施者の判断で元の「色だけを戻す」に差し戻した。**

- ボタンは「チェックマーク」セクションのヘッダーにあり、同セクションに背景色とタイミングが並ぶ
- 同コンポーネントの他セクションの `onClickDefault*` は、そのセクションの全項目を戻している
  （例: `onClickDefaultStepNegativeButton()` は negativeBtn の 4 項目すべて）
- それでも**タイミングだけは対象外**とする。タイミングは見た目ではなく挙動の設定であり、
  「色をやり直す」つもりの操作で巻き添えにしない

**同じ指摘が再度出た場合はこの節を根拠に差し戻すこと。** コード側にも同趣旨のコメントを置き、
`UiGuideEditStylesSettingTour.spec.ts` に「タイミングは変わらない」ことを固定するテストを 2 件入れてある。

### §1 補足2: キーボード操作の確認で分かった標準挙動（2026-09-14）

1-9 を自動化する際、**native の radio グループの標準挙動**を期待値にしないと誤検知する。

- **Tab はグループの先頭ではなく「選択中の項目」に入る。** 先頭固定で期待すると落ちる
- **矢印キーは端で循環する。** 最後の項目で ↓ を押すと先頭へ戻る
- **リングは `:focus-visible` なので、script の `.focus()` では出ない。**
  Chromium は直前の操作がキーボードかどうかで出し分ける。実際に Tab を押して到達させること。
  また、リングが出るのは**そのとき選択されている radio**の隣接要素なので、測る対象を取り違えない

dev 実機での確認結果（16/16）: Tab 到達 / `display` が `none` でない / 不可視かつ極小で流れの外
（`opacity:0`・`position:absolute`・2x2px）/ `:focus-visible` 成立 / リング `solid 2px` /
矢印キーで選択が動く / Tab でグループを抜ける / クリック時はリングが出ない。

### §2 実施中に発見・修正した不具合（2026-09-10）

**タイミングのパネルが開きっぱなしになり、チェック色のカラーピッカーを覆って操作を妨げる**（実施者の実機確認で発見）。

- 修正: パネルはボタンのクリックで開閉し、画面外クリック・他のポップアップが開いた時・選択確定で閉じる
  （`CheckmarkTimingBtn.vue`。あわせて `BasePulldown` に `isOnlyOpen` の転送を追加 — パネル内に入れ子にした
  プルダウンが開いた瞬間に親パネルが閉じる副作用を防ぐため）
- 再発防止: ユニットテスト 5 件（`checkmarkTimingBtn.test.ts`）と実機検証 4 項目
  （選択だけでは開かない / ボタンで開く / チェック色を押すとパネルが閉じてピッカーが出る / 画面外クリックで閉じる）

### §4 補足: 途中ステップでチェックが付く不具合があった（2026-09-10）

CodeRabbit のレビューで発覚。`recordLastStepDisplayedGoal()` は最終ステップ以外で早期 return するのに、
チェックを DOM へ即時反映する `markIntroGoalChecked()` を**無条件に呼んでいた**ため、
「ゴールの完了」設定でも途中のステップでチェックが付いていた（＝「ゴールの表示」と同じ挙動）。

**このチェックリストで検知できなかった理由。** 4-5 は「最終ステップまで進めた状態」でイントロを開く
ケースだけを見ており、**途中のステップで開くケースが無かった**。さらに、ゴールを開くとイントロは
閉じるのが通常の流れで、イントロが DOM に無い間は `markIntroGoalChecked()` の `querySelector` が
null を返して no-op になるため、通常操作では表面化しない。

- 修正: 判定を `isLastStepOfGoal()` に集約し、記録側とチェック反映側の両方から同じ判定を呼ぶ
- 再発防止: ユニットテスト（`last_step_displayed` かつ途中ステップでは `markIntroGoalChecked` を呼ばない）
- **項目 4-11 を追加した。** 手動確認では 4-5 と 4-11 を必ずセットで見ること

**2026-09-14 に dev 実機で確認済み（12/12）。** 陽性対照（最終ステップでは `check` になる）を
同じ実行に入れてあるので、「検出できていないだけ」ではないことまで担保している。
管理画面で設定 → 公開 → デモサイトという配信経路ごと通した版でも同じ結果
（`ONB_VIA_ADMIN=1 node docs/testing/scripts/onbs-1991/s4-11-midstep.mjs`）。
