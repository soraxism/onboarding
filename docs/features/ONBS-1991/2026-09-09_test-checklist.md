### §2 実施中に発見・修正した不具合（2026-09-10）

**タイミングのパネルが開きっぱなしになり、チェック色のカラーピッカーを覆って操作を妨げる**（実施者の実機確認で発見）。
原因はパネルの開閉をゴール一覧の選択状態に直結させていたことで、一度開くと閉じる手段がなかった。

- 修正: パネルはボタンのクリックで開閉し、画面外クリック・他のポップアップが開いた時・選択確定で閉じる
  （`CheckmarkTimingBtn.vue`。あわせて `BasePulldown` に `isOnlyOpen` の転送を追加 — パネル内に入れ子にした
  プルダウンが開いた瞬間に親パネルが閉じる副作用を防ぐため）
- 再発防止: ユニットテスト 5 件（`checkmarkTimingBtn.test.ts`）と実機検証 4 項目
  （選択だけでは開かない / ボタンで開く / チェック色を押すとパネルが閉じてピッカーが出る / 画面外クリックで閉じる）
- 反映: `develop` へマージ済み・ストア申請済み（dev 1.53.0）

### プレビュー / ビューワー拡張が自動操作できない理由（2026-09-10 調査）

読み込み自体は成功する（`check-extensions.mjs` は 8/8 OK）が、**ツアーを起動して操作するところまでは通らない**。

| 拡張機能 | 状況 |
|---|---|
| プレビュー | content script が `chrome.storage` / background に到達できず（`Could not establish connection. Receiving end does not exist.`）、起動要求の postMessage に応答が返らない。永続プロファイル・service worker の暖機・実 operation_token の付与をいずれも試したが変わらなかった |
| ビューワー | ガイドは配信されるが、同じページの埋め込みタグ経由と切り分けられず、ランチャーも表示されない |

**残るリスクは限定的**と判断している。根拠は次の 2 点。

- チェックマークの判定ロジックは配信経路に依存しない共通の SDK コード。タグ経路（§3・§4）と旧側（§9-2）で確認済み
- 設定値はプレビュー用データ（`steps_json_src`）にも保存されることを確認済み（§8-3・§8-4 で editor-api の GET が返す値で確認）

したがって §9-3・§9-4 で追加的に確認したいのは「拡張機能の UI から起動したときに設定が届くか」の一点。ここは人が実施する。

| 10-2 | 設定を「ゴールの表示」に変えて同じ操作 | レポートの数値の出方は 10-1 と変わらない（**設定はレポートに影響しない**） | |

## 自動テストで担保済みの範囲（手動確認は不要）

| 内容 | 担保しているテスト |
|---|---|
| 設定の読み取り（未設定・未知の値は既定へ倒す） | `onboarding-web` ユニット `GoalRepository.test.ts` |
| 最終ステップ表示の記録（境界・重複・壊れた値） | 同上 |
| チェック判定の切り替え（既定 / 完了時 / 論理和） | `onboarding-web` ユニット `onboarding-init.test.ts` + `onboarding-e2e-test` の `goalCheckmarkTiming` |
| 削除済みゴールIDの掃除 / 壊れた値でランチャーが出ること | `onboarding-web` ユニット `onboarding-init.test.ts` |
| 既定設定で DOM 操作が走らないこと | `onboarding-web` ユニット `stands.onbd.test.ts` |
| 記録が失敗しても表示トラッキングが落ちないこと | 同上 |
| 進行中のイントロDOM更新 | `onboarding-web` ユニット `TourIntro.test.ts` |
| 実際にゴールを完了したときの新キー記録 | `onboarding-e2e-test` の `goalCompleted` |
| 管理画面の設定UI（既定値・保存・再読込） | `onboarding-manage-web` の spec + Storybook |

**E2E の制約**: `onboarding-e2e-test` の legacy モードは dev 環境に配信済みの JS を使うため、
ローカルの変更が反映されない（next モードのみローカルビルドを差し込める）。
**旧側（`src/js/`）の挙動は §9-2 の手動確認が唯一の検証経路**なので必ず実施すること。

## 補足: 確認しなくてよいこと

- **レポートの完了数の変化** — レポートは元から「最終ステップの表示」で集計しており、今回の変更で数え方は変わらない
- **`onb_complete_goals_` の書き込みタイミング** — 変更していない（終了ボタン押下のまま）
- **ポップアップの挙動** — ポップアップはイントロに出ないため表示上の変化はない
  （バッジの数え方は従来どおりポップアップも含む）
