dev での確認内容は [2026-09-09_test-checklist.md](./2026-09-09_test-checklist.md) にあり、

認証情報は `docs/testing/credentials.local.md`（git 追跡外）にある。**値をこのファイルへ転記しないこと。**

## 1. リリースが配信に届いたかの確認（最初に行う）

**S3 アップロードと CDN キャッシュ削除は実施者が行う。** 届いたかどうかは配信の実物で見る。
`0` なら未反映。**リリース前は新旧とも `0`**（2026-09-15 時点で確認済み）。

```bash
for p in 391 392; do
  printf 'pid=%s %s\n' "$p" \
    "$(curl -s "https://api.onboarding-app.io/v1/onboarding-init?aid=312&pid=$p" | grep -c onb_last_step_displayed_goals_)"
done
```

新旧の取り違えは `jQuery JavaScript Library` の有無で判別する（**旧JS にだけ含まれる**）。
prod ビルドは LICENSE コメントが落ちるため、dev のように先頭コメントでは判別できない。

## 2. 確認項目

検証用ツアーは prod に新規作成してよい（許可済み）。**プロダクト 391 と 392 の両方に 1 本ずつ**作る。
ステップが 3 つ以上のゴールを 2 つ以上、加えて 1 ステップだけのゴールを 1 つ含める。

| # | 対象 | 内容 | 根拠となる dev 項目 |
|---|---|---|---|
| P-1 | 管理画面 | イントロタブに「チェックマークを付けるタイミング」が出る／既定は「ゴールの表示」 | 1-1〜1-3 |
| P-2 | 管理画面 | 「ゴールの完了」を保存 → 再オープンで保持。背景色と相互に消し合わない | 1-4 / 1-6 |
| P-3 | 旧JS（391） | 既定設定で**従来どおり**（1 ステップ表示でチェックが付く） | 3-1〜3-4 |
| P-4 | 旧JS（391） | 「ゴールの完了」で、最終ステップ表示まではチェックが付かない／表示でチェックが付く | 4-1〜4-7 |
| P-5 | 新TS（392） | P-3 と同じ | 3-1〜3-4 |
| P-6 | 新TS（392） | P-4 と同じ | 4-1〜4-7 |
| P-7 | 新旧共通 | 途中ステップ表示中にイントロを開いてもチェックが付かない（進行中の即時反映の裏取り） | 4-11 |
| P-8 | 新旧共通 | コンソールにエラーが出ない | 7-6 |
| P-9 | 拡張機能 | ストア審査通過後、エディタ拡張でタイミングを変更 → 管理画面に反映 | 2-1〜2-6 |

- **P-9 はストア審査の通過待ち**のため、P-1〜P-8 とは別タイミングになる。審査状況の確認は実施者が行う
- カスタム JS ツアー（tour 13）は既定設定である限り API 分岐に入るため、リリース後の再確認は必須ではない

## 4. 自動化スクリプトを prod へ向けるときの改修点

dev 用スクリプトは [docs/testing/scripts/onbs-1991/](../../testing/scripts/onbs-1991/) にあるが、
**dev のホストとプロダクト ID を直接持っている**ため、そのままでは prod に使えない。

| ファイル | 直すところ |
|---|---|
| `docs/testing/scripts/lib/manage.mjs` | `PRODUCTS` の `productId`（247/248 → 391/392）と `demoUrl`（`?env=prod` を付ける）、`blockSelfGuides()` の `manageHost` |
| `docs/testing/scripts/onbs-1991/lib.mjs` | `TOURS`（prod で作った検証ツアーの ID に差し替え） |

環境の切り替えは引数か環境変数で持たせ、**dev の値を消さずに prod を足す**（dev 側の再実行が効かなくなるため）。
