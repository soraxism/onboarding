# イントロのチェックマーク タイミング設定 仕様まとめ

> 対象: 営業・カスタマーサクセス（売り方の整理／ヘルプ記事作成用）
> 状態: リリース済み仕様（2026-09-16 本番リリース・動作確認完了時点）

---

## 1. この機能とは

ツアーのイントロ（ゴール一覧）に並ぶ**チェックマークが、どの時点で付くかを管理画面から選べる**ようにした設定です。

これまでチェックマークは、**ゴールを開いて 1 ステップ目が表示された時点**で付いていました。
途中で閉じてもチェックが付いたままになるため、「どのゴールをやり切ったか」がエンドユーザーに伝わりません。

本対応で、**「ゴールの表示」/「ゴールの完了」の 2 択**をツアーごとに選べるようになりました。

### この設定が解決すること

| お客様の声 | 本設定での解き方 |
|---|---|
| 開いただけでチェックが付くので、やり残しが分からない | 「ゴールの完了」を選ぶと、最後のステップを見るまでチェックが付かない |
| レポートの完了数とイントロの見え方が合わない | 「ゴールの完了」はレポートの完了集計と**同じ基準**（最後のステップの表示） |
| 個別カスタム JS でチェック制御をしている | 標準機能で同じことができる（移行手順は別ドキュメント） |

---

## 2. 提供対象（重要 / 営業向け）

**すべてのプロダクトで使えます。** 配信コードがリファクタ前・リファクタ後（`use_refactored_onboarding_init` フラグの有無）のどちらであっても動作します。

- リファクタ前・リファクタ後の配信コード**両方に同時実装**しているため、バルーン機能のような提供対象の制限はありません
- 設定 UI は**管理画面とブラウザー拡張機能（エディター）の両方**にあります。どちらで変えても同じ値が保存されます
- **対象はツアーのみ**です。イントロを持たないポップアップ・ヒント・バルーンには関係ありません

### 既存のお客様への影響

**既定値は現行どおりの「ゴールの表示」です。設定を変えない限り、見え方は一切変わりません。**

この「既定では何も変わらない」ことが本対応の前提で、本番リリース後の確認でも最優先項目として検証済みです
（リファクタ前の配信コード 18/18・リファクタ後の配信コード 18/18 OK）。

---

## 3. 用語

| 用語 | 意味 |
|---|---|
| **イントロ** | ツアーを開いたときに最初に出る、ゴールの一覧画面 |
| **ゴール** | イントロに並ぶ 1 件。複数のステップで構成される |
| **チェックマーク** | イントロのゴール一覧で、済んだゴールに付く印。背景色は従来どおり設定可能 |
| **ランチャーのバッジ** | ランチャーに出る未完了ゴール数。**チェックマークと同じ判定で数えている** |

---

## 4. 設定の流れ

### 管理画面から設定する

1. ツアー編集画面を開く
2. ヘッダーの「**表示スタイル設定**」を開く
3. 「**イントロ**」タブ →「**チェックマーク**」セクション（背景色を設定している場所と同じ）
4. 「**チェックマークを付けるタイミング**」で 2 択から選ぶ
5. 保存する

### ブラウザー拡張機能（エディター）から設定する

1. 拡張機能でツアーを開き、イントロの**ゴール一覧をクリックして選択**する
2. インラインメニューの「**チェックのタイミング**」を押す
3. プルダウンから選ぶ（選んだ時点で保存されます）

> 管理画面と拡張機能は同じ設定を見ています。片方で変えた値はもう片方にも反映されます。

---

## 5. 設定項目

### 5-1. チェックマークを付けるタイミング

| 選択肢 | チェックが付くタイミング | 備考 |
|---|---|---|
| **ゴールの表示（いずれかのステップが表示）** | ゴールを開いて **1 ステップ目が表示された時点** | **既定値**。従来どおりの挙動 |
| **ゴールの完了（最後のステップが表示）** | そのゴールの**最後のステップが表示された時点** | レポートの完了集計と同一基準 |

- 設定の単位は**ツアーごと**です。ゴールごと・プロダクトごとには設定できません
- 一度も保存していないツアーは「ゴールの表示」として扱われます
- 「**終了ボタンを押したとき**」という選択肢は**ありません**（2 択のみ）
- 入力部品は**カード型のラジオボタン（縦並び）**で、選択中のカードが枠と背景色で分かります

### 5-2. 「デフォルトに戻す」の対象

「チェックマーク」セクションの「デフォルトに戻す」は、**背景色だけ**を既定色（`#46a6ff`）に戻します。
**タイミングの選択は戻りません。**

> 見た目のやり直しのつもりで押した操作で、挙動の設定まで巻き添えにしないための仕様です。

---

## 6. 閲覧側（お客様のサイト）での挙動

### 設定ごとの比較

| エンドユーザーの操作 | ゴールの表示（既定） | ゴールの完了 |
|---|---|---|
| ゴールを開いて 1 ステップ目を見て閉じた | **✓ 付く** | ✗ 付かない |
| 途中のステップまで進めて閉じた | ✓ 付く | ✗ 付かない |
| **最後のステップを表示した**（終了ボタンは押していない） | ✓ 付く | **✓ 付く** |
| 最後のステップで「終了」ボタンを押した | ✓ 付く | ✓ 付く |
| ステップが 1 つだけのゴールを表示した | ✓ 付く | **✓ 付く**（1 ステップ目＝最後のステップ） |

### チェックが画面に反映されるタイミング

- **ツアーを進めている最中でも即座に反映されます。** 最後のステップを表示した状態でイントロを開くと、
  そのゴールにはもうチェックが付いています
- 逆に、途中のステップを表示している状態でイントロを開いても、「ゴールの完了」設定ではチェックは付きません
- チェックマークの背景色は従来どおり、イントロを開いたときに設定値が適用されます

### ランチャーの未完了ゴール数（バッジ）

**チェックマークと同じ判定で数えるため、設定に連動して数字が変わります。**

- 「ゴールの完了」にすると、最後のステップを見るまでバッジの数字が減りません
- **この連動は管理画面の設定欄には書いていません。**未完了ゴール数の表示自体があまり使われておらず、
  注記がノイズになるためです。仕様としては連動します（お問い合わせがあった場合はこの節を根拠に説明してください）

### 特殊なゴールの扱い

| ケース | 「ゴールの完了」設定での挙動 |
|---|---|
| **ゴール連結**があるゴール | 最後のステップを表示した時点でチェックが付く（連結先へ進む前）。**仕様として許容**しています。レポートの完了集計も同じ基準のため、レポートとイントロの数は一致します |
| **ステップ分岐**で最後のステップを通らないルート | チェックは**付きません**（レポートの完了集計と同じ基準） |

## 7. 設定を切り替えたときのチェックマークの引き継ぎ（要周知）

「ゴールの表示」で運用していたツアーを「ゴールの完了」へ切り替えると、**既存エンドユーザーのチェックの一部が外れます。**

| これまでのエンドユーザーの状態 | 切替前の見え方 | 「ゴールの完了」へ切替後 |
|---|---|---|
| 最後まで進めて「終了」ボタンを押した | ✓ | **✓ 維持される** |
| **最後のステップを表示して × で閉じた（2026-09-16 のリリースより前）** | ✓ | **✗ 外れる** |
| 最後のステップを表示して × で閉じた（リリース後） | ✓ | ✓ 維持される |
| 途中まで見て閉じた | ✓ | ✗ 外れる（**設定変更の意図どおり**） |
| 未着手 | ✗ | ✗ |

- リリース以降は、設定に関わらず「最後のステップを表示した」記録を常に取っているため、
  **リリース後に到達した分は設定を変えても引き継がれます**
- 引き継げないのは**リリース前に「最後のステップまで見たが終了ボタンを押さなかった」分だけ**です。
  この履歴は記録が存在せず、遡って復元できません
- 「ゴールの表示」へ**戻すことはいつでもできます**。戻せばチェックも元どおり付きます

### チェックが消える例外（設定に関係なく従来から同じ）

チェックの記録はエンドユーザーのブラウザーに保存されるため、次の場合は設定に関わらず消えます。

- ブラウザーのデータ削除 / シークレットウィンドウ / 別の端末・別ブラウザー・別ドメイン
- サイト側の他のスクリプトによるストレージ全消去
- プレビューの開始・終了時のリセット

**今回の変更で新たに増えた例外はありません。**

## 8. レポートとの関係

**レポートの数値は一切変わりません。**

- レポートの「ゴール完了」は、**もともと最後のステップの表示**で集計されています
- 「ゴールの完了」を選ぶことは、**イントロの見え方をレポートの完了定義に合わせる**操作にあたります
- 「ゴールの表示」のままでも、レポートの集計は従来どおりです

| 機能 | 「完了」の基準 | 本対応での変化 |
|---|---|---|
| レポート（完了UU） | 最後のステップの表示 | 変化なし |
| イントロのチェックマーク | 設定で選択（既定は 1 ステップ目の表示） | **ここだけが変更点** |
| 自動表示条件の「完了済み」/ 公開API | 終了ボタン押下 | 変化なし |

> 自動表示条件で「ゴールが完了済みのとき」を使っているツアーの出し分けは、本設定を変えても**影響を受けません**。

## 9. 影響する周辺機能

| 対象 | 影響 |
|---|---|
| 公開API `setCheckedGoalIds()` | **この API を使っているお客様では本設定が効きません**（API の指定が優先されます）。標準機能へ移す手順は [2026-09-14_api-to-setting-migration.md](./2026-09-14_api-to-setting-migration.md) を参照 |
| 個別カスタム JS | 独自にチェック状態を描いているツアーがあります。**既定値のままなら影響はありません** |
| 自動表示条件・公開API・レポート | **変化なし** |
| ポップアップ・ヒント・バルーン | **対象外**（イントロを持たないため） |

---

## 10. できないこと（制限一覧）

| 項目 | 状況 |
|---|---|
| ゴールごとにタイミングを変える | **不可**（ツアー単位の設定） |
| プロダクト全体に一括で設定する | **不可**（ツアーごとに設定） |
| 「終了ボタンを押したとき」を基準にする | **不可**（選択肢は 2 択） |
| 設定切替時に「最後のステップを見たが終了していない」過去分を引き継ぐ | **不可**（リリース前の分は記録がない。§7） |
| 「デフォルトに戻す」でタイミングも戻す | **不可**（背景色のみが対象。仕様） |
| ランチャーのバッジだけ別基準で数える | **不可**（チェックマークと常に連動） |
| 公開API `setCheckedGoalIds()` と併用して設定を効かせる | **不可**（API が優先。移行が必要） |
