**実施日**: 2026-10-02（金）15:00 - 16:00
**シナリオ**: 管理画面のログインレポートCSVダウンロード機能の不具合で、他社プロダクトのデータが混入したCSVを顧客がダウンロードできていた
**実施モード**: **モードC Slack完結型**（主催側からは会議を設定しない。開始・終了ともSlackで告知し、振り返りもスレッドで完結）
**記録係**: 空（ファシリテーター兼任）
**ファシリテーター**: 空（**対応メンバーとしては「休暇で不在」の設定**。属人化の測定を兼ねる）

> - **A社** … CSVを受け取り、混入を指摘してきた取引先

## Part 2. 確認漏れチェック【ファシリテーター】

アンケートの集約結果に以下が含まれているか確認します。**含まれていなければ、別途フローへ反映してください。**

### 体制・判断

- [ ] 一次受け（営業/CS）から責任者へのエスカレーション先は決まっているか
- [ ] **特定の個人が不在でも初動が回るか**（今日の「空さん不在」で詰まった箇所はどこか）
- [ ] 「疑い」の段階で上げてよいという合意はあるか
- [ ] 「知った時」を記録する運用はあるか
- [ ] 証跡保全の手順はあるか
- [ ] 委託／自社取得の契約上の整理を、誰が答えられるか
- [ ] 法務・顧問弁護士への相談ルートと連絡先はあるか
- [ ] 公表判断の権限者は決まっているか
- [ ] 報道対応の窓口は決まっているか

### リモート / Slack運用

- [ ] **インシデント発生時にどこに集まるか決まっているか**（専用チャンネルの命名規則・ハドル運用）
- [ ] **DMで判断を閉じないルールはあるか**
- [ ] **顧客との共有チャンネルと社内チャンネルの使い分けルールはあるか**
- [ ] **音声で決めたことをSlackに書き戻すルールはあるか**
- [ ] **Slackが見られない時間帯・状況の代替連絡手段はあるか**（電話番号リストの有無）
- [ ] 夜間・休日の連絡経路はあるか
- [ ] Slack上の証跡（メッセージ・共有ファイル）を消さない・保全する手順はあるか

### 対外対応・技術

- [ ] 顧客への通知文テンプレートはあるか
- [ ] 削除依頼・削除証明の書式はあるか
- [ ] **ログインレポートの各列のうち、どれが個人情報にあたるかを整理した資料はあるか**
- [ ] **カスタムクエリに顧客が何を入れているかを把握しているか**（把握していないなら、漏えい範囲を確定できない）
- [ ] **集計ロジックのプロダクト絞り込みの誤りを、リリース前に検知する仕組みはあるか**
- [ ] **顧客のダウンロード操作ログは残っているか。影響範囲の確定に使えるか**
- [ ] **不具合の疑いがある機能を一時停止する判断は、誰の権限か**
