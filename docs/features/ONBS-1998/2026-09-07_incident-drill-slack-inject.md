# 個人情報漏えい 机上訓練 Slack投入用テキスト

**実施日時**: 2026-10-02（金）15:00 - 16:00
**用途**: 机上訓練のインジェクト（情報投入）を、実際のクライアント連絡と同じSlackで行うための文面集
**シナリオ**: 管理画面のログインレポートCSVダウンロード機能の不具合で、他社プロダクトのデータが混入したCSVを顧客がダウンロードできていた
**投稿者**: ファシリテーターが「取引先A社 田中さん」役として投稿する
**前提**: 全員リモート。連携はSlack
**実施モード**: **モードC（Slack完結型）** — **主催側からは会議を設定しない。** 開始告知・インジェクト・振り返り・クロージングをすべてSlackで行う（参加者が自分でハドルを立てるのは自由）

---

## ⚠️ 実施前に必ず読むこと

| # | 厳守事項 |
|---|---|
| 1 | **実際のクライアントとのSlackチャンネル（Slack Connect含む）には絶対に投稿しない。** 誤爆すると本物のインシデントになります |
| 2 | 訓練専用チャンネルを新規作成する。**チャンネルトピックに「【訓練用】ONBS-1998 机上訓練専用」と明記する** |
| 3 | **シナリオは誰にも事前共有しない**（藤原さんも訓練の対象）。停止権限はファシリテーターが持つ。オブザーバー（経営層）を置ける場合のみ、その人にだけ共有する |
| 4 | **訓練は必ずその日のうちに終了させ、ネタバラシまで行う。** 持ち帰らせない |
| 5 | 参加者が本物のクライアントや社外に連絡しようとしたら、**即座に訓練であることを明かして止める** |

## チャンネル構成

**片方だけを用意する。** 社内対応用チャンネルを参加者が自分で立てるかが観測点になる。

| チャンネル | 用意するか | 役割 |
|---|---|---|
| `#2026_個人情報漏えい訓練` | **ファシリテーターが作る** | A社との共有チャンネル想定。田中さん役として投稿する場。参加者全員を招待 |
| 社内対応用チャンネル | **あえて用意しない** | 参加者が作るかを観測する。作らなければそれ自体が発見 |

- **会議（Meet / ハドル）は主催側からは設定しない。** 参加者が自分で立てるのは自由（立てるかどうかが観測点）
- **A社との共有チャンネルで参加者が社内調整を始めても止めない。** 実際なら顧客に全部見えていた、という材料になる

### 抜き打ち度の選択

| レベル | やり方 | 向いている場面 |
|---|---|---|
| **推奨（今回はこれ）** | 事前に「今日1時間、訓練をやります」と伝えたうえで、開始時にSlackへ投稿 | 初回。安全で、かつ十分に緊張感が出る |
| 完全抜き打ち | 予告なしにSlackへ投稿し、反応を見る | 2回目以降。責任者への事前共有と、90分での強制終了ルールを必ずセットにする |

**今回は「予告あり × モードC（Slack完結型）」の組み合わせで実施します。**
実施日時は予告しつつ、主催側からは会議を設定しません。参加者は通常業務の合間に反応する状態になり、
**通知に気づくか・片手間で初動が回るか**を観測します。
完全抜き打ちは、フローが整備されてからの実力テストに取っておいてください。

## オープニング告知（0:00）

**投稿先**: `#2026_個人情報漏えい訓練`
**投稿者**: ファシリテーター（`@channel` を付ける）

> 主催側から会議を設定しないため、**この投稿がオープニングそのもの**になる。
> 長文は読まれない。冒頭3行に「1時間」「このチャンネルだけ見る」「終了時刻」を置く。

> **「会議はやりません」とは書かない。** ハドルやMeetを立ててはいけない、と受け取られる。
> 伝えたいのは「**こちらからは会議を設定しない**」であって、参加者が自分で立てるのは自由
> （むしろ立てるかどうかが観測点）。

```
@channel 【訓練開始】個人情報漏えいの机上訓練を始めます（15:00〜16:00）

・これから1時間、このチャンネルに連絡が流れます
・こちらからは会議を設定しません。普段の仕事をしながら、いつもどおり対応してください
　（必要だと思ったら、ハドルでもMeetでも自由に立てて構いません）
・実際のシステムには触りません。すべて架空の設定です

■ このチャンネルについて
このチャンネルは「*A社さんとの共有チャンネル（Slack Connect）*」という想定です。
ここに書いたことは、*すべてA社さんに見えている*と思って扱ってください。

■ 本番のつもりで動いてください
設定は架空ですが、*動き方は本番と同じにしてください。*
・「実際ならこうします」ではなく、*実際にやってください*（社内への連絡・判断・記録）
・A社さんへの返信も、*そのまま送る文面*をこのチャンネルに書いてください
・時間感覚も本番と同じです。「後で調べます」で止めず、*誰が・いつまでに、まで決めてください*
・ただし、*社外への実際の連絡と、実システムの操作だけはしないでください*

訓練だからと省略した動きは、本番でも省略されます。そこが今日いちばん見たいところです。

■ 今日のゴール
「うまく対応できること」ではありません。
*「決められなかったこと」を見つけること*がゴールです。
詰まったら、詰まったと書いてください。それが今日いちばん価値のあるアウトプットです。

■ ルール（4つだけ）
1. DMを使いたくなったら、先にこのチャンネルに「〇〇さんにDMします」と書いてください
2. 実際のシステムやコンソールは開かないでください
3. ハドルやMeetを立てるときは、記録のため @空 を入れてください
　（私は聞いているだけで、対応はしません。記録のための同席です）
4. ハドルや通話で決めたことは、必ずSlackに書き戻してください

■ 役割
一次受け: @椎名 ／ 統括判断: @藤原 ／ 調査: @鈴木 @文
進行: @空（私です）

■ 今日、私（空）は「休み」です
普段この手の対応には私も事実確認で入りますが、*今日は休暇で不在という設定*です。
進行役としてこのチャンネルにはいますが、*対応メンバーとしては存在しません。*
私に事実確認や判断を振らないでください（進め方の質問だけ受け付けます）。

実際のインシデントは、誰かが休みの日にも起きます。その日でも回るかを見たいためです。
```

> **「A社との共有チャンネルである」と先に明かすことで、観測の意味が変わる。**
> 「気づくか」ではなく「**分かっていても、つい社内の相談を書いてしまうか**」を見ることになる。
> 実際のSlack Connectでも共有チャンネルだと知ったうえで使うので、こちらのほうが本番に近い。
> 書いてしまっても**止めない。** 回数を数えて振り返りで示す。

## ファシリテーター用 応答パターン集

訓練中、参加者が「A社」に返信してきたときの応答例です。
**参加者の判断の甘さが、そのまま不利な展開として返ってくる**ように設計しています。

| 参加者の返信 | A社役の応答 | 狙い |
|---|---|---|
| 「すぐ削除していただけますか」 | 「承知しました、削除しました。（少し置いて）……あ、もう手元にファイルは残っていません」 | 証拠が消えたことに気づかせる |
| 「削除せずお待ちください」 | 「承知しました。こちらで保管しておきます」 | 正しい判断。そのまま進める |
| **「Slackのファイルも消してください」** | 「消しました。Slackの履歴からも消えています」 | **Slack上の証跡も消えることに気づかせる** |
| 「確認しますのでお待ちください」（時間の言及なし） | 「いつ頃までにご回答いただけますでしょうか。弊社でも社内報告が必要でして」 | 期限のコミットを迫る |
| 「調査中です」だけで30分放置 | 「その後いかがでしょうか。弊社の情報システム部から状況確認を求められております」 | 中間報告の必要性に気づかせる |
| 「何件くらい混ざっていましたか」と聞かれる | 「弊社では正確には分かりません。ざっと見ただけで数十件は目に入りました」 | 相手任せにできないことを示す |
| 「社外に共有していませんか」 | （インジェクト④を前倒しで投入してよい）「実は共有フォルダに置いてしまっていて……」 | 良い質問には情報で報いる |
| 「削除証明書をいただけますか」 | 「どういった形式で出せばよいでしょうか。書式をいただければ対応します」 | 書式がないことに気づかせる |
| **「一度お電話でお話しできますか」** | 「はい、大丈夫です。ただ、後で経緯を確認したいので**記録は残していただけますか**」 | 音声で決めたことを書き戻す必要性に気づかせる |
| 謝罪だけで具体的な次アクションがない | 「恐れ入りますが、弊社としてはいつまでに何をご報告いただけるか知りたいのですが」 | 対外コミュニケーションの型がないことを露呈させる |
| 「弊社の個人情報保護管理者から改めてご連絡します」 | 「承知しました。お待ちしております」 | 正しい判断。そのまま進める |
