## 2. 実施の概要

| 項目 | 内容 |
|---|---|
| 目的 | インシデント対応フローを整備するにあたり、**現状で決められないことを洗い出す** |
| 形式 | 机上訓練。実システムには一切触れない |
| 実施方法 | **Slack完結型。**会議体を設けず、参加者は通常業務と並行して対応 |
| 参加者 | ISMS管理者・CS・エンジニアを含む11名（投票参加者数） |
| シナリオ | 管理画面のCSVダウンロード機能の不具合により、顧客が取得したCSVに他社データが混入 |
| 事前共有 | **進行役1名を除き、シナリオは誰にも共有していない**（ISMS管理者を含む） |

**会議を設けなかった理由**: 実際のインシデントは通常業務中にSlackで始まります。
通知に気づくか、片手間で初動が回るかは、会議を設定した訓練では測れないためです。

## 4. 今後の対応

見つかった空白は、担当と期限を付けたアクションとして管理を開始しています（12件）。

**現時点では担当・期限の割り当てが完了していないため、本提出資料には含めていません。**
進捗および今後の計画については、**審査時に口頭でご報告します。**

| 予定している対応 | 概要 |
|---|---|
| 対応フローの整備 | 上記の空白1〜8を章立てとしたドラフトを作成し、関係者レビューを経て確定 |
| 技術面の点検 | 集計処理のリリース前チェック、操作ログの保全状況の確認 |
| 確認方法 | **訓練の再実施は行わず**、ドラフトの関係者レビューで確認 |

技術面の点検は、**今回の不具合が架空である**ことから「再発防止」ではなく
**「同じことが起こり得る箇所の未然点検」**として扱います。
