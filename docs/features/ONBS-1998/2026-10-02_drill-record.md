## 2. シナリオ（架空）

管理画面のログインレポートCSVダウンロード機能の不具合により、顧客が自分でダウンロードした
CSVに他社プロダクトのデータが混入していた。顧客からの指摘で発覚する。

| 投入した情報 | 内容 |
|---|---|
| 第一報 | 取引先から「ダウンロードしたCSVに弊社のものではないユーザーグループ名が含まれている」 |
| 原因 | 集計クエリのプロダクトID絞り込みが一部で無効化。先月のリリースから混入 |
| 規模 | 他社プロダクト3件・ユニークユーザー1,240名。同期間に同レポートを取得した顧客は計5社 |
| 二次拡散 | 受領側が社内共有フォルダに保存、10名程度が閲覧可能だった |

## 4. 測定結果

### 対応時間

| 項目 | 結果 |
|---|---|
| 第一報 → 最初の反応 | **約2分** |
| 第一報 → ISMS管理者へ到達 | **約10分** |
| 「疑い」として調査・顧客連絡が決まるまで | 約16分 |
| CS → エンジニアへ調査依頼 | 17分 |
| 原因・発生期間の特定 | 29分 |
| **修正リリース完了（止血）** | **48分** |

### 対応の広がり

| 項目 | 結果 |
|---|---|
| 影響範囲が「指摘してきた1社」に閉じないと気づいた時点 | 23分（調査報告の「全顧客が使える機能」を受けて） |
| 影響範囲が「閲覧された側の顧客」にも及ぶと気づいた時点 | 49分 |
| 全顧客への周知 ＋ 影響顧客への個別報告の方針決定 | 59分 |
| 混入元3社（データの持ち主）への通知方針 | **未決**（時間内に議題化せず） |

### 運用・規律

| 項目 | 結果 |
|---|---|
| 社内対応用チャンネルの作成 | **作られなかった**（既存3チャンネル・5スレッドに分散） |
| 顧客との共有チャンネルに社内の議論が流れた回数 | **1回**（注意後は発生せず） |
| ハドル・通話の発生 | **なし**（全編テキストのみ） |
| 実システム（管理画面・本番DB・コード）への接触 | **なし**（ルールどおり） |
| 証跡保全の指示 | **出なかった** |
| 調査体制 | 依頼は**エンジニア2名宛**。実際に応答・調査・修正を行ったのは**1名**（2人目は入らず） |
| 機能の一時停止の判断 | 議題化せず（修正で対応） |

| 選択肢 | 人数 |
|---|---|
| 報告対象だと思う | **9名** |
| 報告対象ではないと思う | 1名 |
