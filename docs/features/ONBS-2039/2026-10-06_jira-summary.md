# 管理 API の不具合・セキュリティ上の問題を直す（ONBS-2039 のレビューで発見）

> このファイルは ONBS-2039 そのものの概要ではない。ONBS-2039 のレビュー中に見つかった、管理 API 側の問題を**新しく起票するための概要**。チケットを切ったら、そのチケットのディレクトリへ移す。

詳細ドキュメント:
- 問題ごとの現状・根拠（パス:行）・影響・推奨: [2026-10-06_be-issues-survey.md](./2026-10-06_be-issues-survey.md)

## 問題点

管理画面のリファクタ（ONBS-2039、onboarding-manage-web PR #1222）のレビューで、FE が前提にしている管理 API の挙動をコードで突き合わせた。その中で、管理 API 側に次の問題が見つかった。

いずれも `onboarding-manage-api` origin/main `29b9fd2b` のコードを読んでの判断で、実 API で試してはいない。

### セキュリティ

| # | 内容 | 優先度 |
| --- | --- | --- |
| BE-1 | カスタムイベントの作成・更新 API で、リクエスト本文のキーが検証されずに SQL の列名へそのまま入る。プロダクトにアクセスできるログイン済みの利用者なら、本来は変えられない列の書き換え、イベントの別プロダクトへの移動、列名部分への SQL 注入を試みられる | **高** |
| BE-2 | 2要素認証を有効にする確認（`/user/tfa/confirm`）で、一時トークンの有効期限（1 時間）が効いていない | 中 |
| BE-3 | 認証コードを確かめる 3 つの API（ログインの 2要素認証・2要素認証の有効化・パスワード再設定）に試行回数の制限が無い（6 桁）。使ったコード・一時トークンも、期限まで消えずに再利用できる | 中（WAF 等の設定次第） |
| BE-4 | パスワード再設定メールの送信 API（`/pw/reminder`）が、未登録のメールアドレスにだけ 404 を返すため、登録の有無が分かる | 低 |

### 不具合

| # | 内容 |
| --- | --- |
| BE-5 | 招待されたユーザーのパスワード設定（`/pw/invited`）で、招待トークンを DB の commit 前に消している。途中で失敗すると、パスワード未設定のまま招待リンクが使えなくなる |
| BE-6 | カスタムイベント作成 API の応答が「プロダクト内で ID が最大のイベント」で、同時に作成されると別のイベントを返しうる |
| BE-7 | `GET /v1/report` の「プロダクトの権限なし」が、`response_401()` の引数漏れで 500 になる |
| BE-8 | `/pw/invited` の `'joinied'` の綴り違い（参加済みでもパスワードを上書きできる）。招待の再送のたびに、使われない招待トークンが作られる |

---

## 対応方針

- **BE-1 を最優先で対応する。** 作成・更新 API で列の許可リストを持ち、検証したキーだけで INSERT / UPDATE を組む
- BE-2: 期限切れを検出したら、一時トークンを無効として扱う
- BE-3: WAF・API Gateway の制限の有無を確認する。無ければ、一定回数の失敗でコード・一時トークンを無効にする。使ったコード・一時トークンは成功時に消す
- BE-4: 未登録のメールアドレスでも 200 を返す
- BE-5: トークンの削除を commit のあとへ移し、応答用の取得を try の中へ入れる
- BE-6: INSERT した行の ID で引き直す
- BE-7: `response_401` に引数を渡す（401 と 403 のどちらが妥当かも決める）
- BE-8: 綴りを直す。再送は `product_ids` で既存のトークンを探す

BE-1〜BE-4 はセキュリティ、BE-5〜BE-8 は不具合なので、チケットを分けてもよい。
