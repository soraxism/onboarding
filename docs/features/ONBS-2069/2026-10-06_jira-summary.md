# AIチャットのモバイル表示に新UI（下部フローティング）を追加する

## 概要

スマートフォンでのAIチャットの表示形式を2種類に増やし、管理画面から選択できるようにする。

| 表示形式 | 内容 | 既定 |
| --- | --- | --- |
| ランチャー（旧UI） | 画面端に縦書きテキスト or 丸アイコンのランチャーを出す。現行の挙動 | ○ |
| フローティング（新UI） | 画面下部に初回選択肢を並べたバーを出す。バーを押すとチャットが開く | |

**旧UIは既存顧客への影響を考えて残す。設定が無いデータはすべて旧UIとして動かす。**

---

## 問題点

現行のスマートフォン表示は、画面端にランチャーを置くだけの導線しかない。

- 何を聞けるチャットなのかが開くまで分からず、初回選択肢（`base.window.shortcuts`）を設定していても
  **チャットを開かないと目に入らない**
- ランチャーが画面端にあり、スクロール中の視線に入りにくい

初回選択肢をチャットの外に出し、スクロール中に目に入る位置へ置くことで、
設定済みの初回選択肢を実際の送信まで繋げる。

---

## 対応方針

### 管理画面

- チャット編集の「ランチャー」ページに **モバイル表示形式** の選択を追加する
- `base.trigger.mobile_ui_type`（`"launcher"` / `"floating"`、未設定時は `"launcher"`）を新設する
- 新UI選択時は「PC・タブレットでは従来のランチャーが表示されます」「初回選択肢が未設定の場合は最初のメッセージが表示されます」を案内する

### エンドユーザー（AIチャットライブラリ）

新UI選択時、**スマートフォンのみ**次の挙動になる。

- 画面下部にフローティングを表示し、初回選択肢の内容を横1列（横スクロール）で並べる
- 初回選択肢が未設定の場合は最初のメッセージを1行表示する（はみ出しは `...`）
- ページトップから **100px** スクロールした時点で表示する（z-index は最前面）
- ページ最下段（残り **100px** 以下）に達したら、サイト下部のコンテンツを操作できるよう表示を消す
- グレーのハンドルバーを押すとチャットが開く
- 初回選択肢を押すとチャットが開き、そのメッセージが送信される
- チャットを開いたとき、サイトとチャットの間にオーバーレイを出す
- `trigger.is_hidden` が有効な場合はフローティングを表示しない
- チャットウィンドウ本体を、全画面からボトムシート（上に余白・角丸・上部にハンドルバー）に変更する

PC・タブレットは新UIを選んでも従来のランチャーのまま。

## 調査で判明した前提

実装前に把握しておくべき点。

1. **旧配信API（`onboarding-api` の `v2/onboarding-init`）は `window.shortcuts` を返していない。**
   新UIは初回選択肢に依存するため、この経路では本来の形で動かない。
   現在この経路の顧客がいないため今回は対応しないが、復活させる場合は `shortcuts` と `mobile_ui_type` の両方を追加する必要がある。

2. **`PATCH /trigger` は trigger 全体を置き換えるため、`mobile_ui_type` 未対応の管理Webから PATCH が来ると設定が消える。**
   `shortcuts` で既に同じ問題に対処済み（`method_patch.py:263-267`）なので、同じパターンの防御を `trigger` にも入れる。

3. **オーバーレイは既に実装済み**（`WindowOverlay.svelte`、`!isPC()` で `rgba(0, 0, 0, 0.2)`）。
   現状はチャットが全画面のため見えていないだけで、ボトムシート化によって上部余白に現れる。新規実装は不要。

4. **`onboarding-web` の `mountWithId()`（STANDSMotion API からの明示マウント）は `is_hidden` を見ない。**
   配信側のフィルタ（`getFilteredChats()`）だけに頼らず、`is_hidden` の判定はライブラリ側にも持たせる。

## スコープ外

- ハンドルバーのドラッグ操作（スワイプで閉じる・高さ変更）。見た目のみ実装する
- 旧配信API（`onboarding-api`）への対応
- 管理画面プレビューをSPモードで動かす改修（静的な見本で代替する）
- PC・タブレット向けのフローティング表示
- トラッキングイベントの新設（既存の `window_opened` / `message_sent` を流用する）
