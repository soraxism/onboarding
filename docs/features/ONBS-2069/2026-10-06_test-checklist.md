# ONBS-2069 テスト項目書

dev 環境での手動確認項目。実施手順は [docs/testing/README.md](../../testing/README.md) を参照する。

**新UIはスマートフォン限定**のため、実機またはブラウザのデバイスモード（iPhone 等）で確認する。
PC の UA のままだと `isSP()` が false になり、常に旧UI（ランチャー）が出る。

自動テストで担保済みの項目には「自動」と記す。ライブラリの `npm test` と `npx playwright test` で実行される。

---

## 1. 管理画面（onboarding-manage-web）

チャット編集 → ランチャー ページ。

| # | 確認内容 | 期待 | 自動 |
| --- | --- | --- | --- |
| 1-1 | 新規チャットを作成し、ランチャーページを開く | 「スマートフォンでの表示形式」が **ランチャー** になっている | |
| 1-2 | フローティングを選ぶ | 選択が保存され、画面を再読み込みしても保持される | |
| 1-3 | フローティング選択時の注記 | 「パソコン・タブレットでは…ランチャーを表示します」が出る | |
| 1-4 | 初回選択肢が未設定の状態でフローティングを選ぶ | 「初回選択肢が未設定のため、最初のメッセージが1行で表示されます」が出る | |
| 1-5 | 初回選択肢を設定してから開き直す | 1-4 の案内が消える | |
| 1-6 | 既存チャット（この設定を持たないデータ）を開く | エラーにならず、**ランチャー**が選択された状態で表示される | ○ |
| 1-7 | 「ランチャーの表示」を「しない」にする | 表示形式の選択もグレーアウトされ、操作できない | |
| 1-8 | 公開する | 公開後の設定が配信に反映される（3-1 で確認） | |

### 1-9. 旧バージョンの管理画面からの上書き（重要）

`PATCH /trigger` は trigger 全体を置き換えるため、未対応バージョンからの更新で設定が消えないことを確認する。

| 手順 | 期待 |
| --- | --- |
| フローティングを選んで保存 → **本変更を含まない管理画面**（本番等）から同じチャットのランチャー設定（テキスト等）を変更して保存 → 本変更を含む管理画面で開き直す | **フローティングのまま**（ランチャーに戻っていない） |

## 4. デグレ確認（最優先）

既存顧客への影響がないことを確認する。**ランチャーを選んだチャットは一切変わらないこと。**

| # | 確認内容 | 期待 | 自動 |
| --- | --- | --- | --- |
| 4-1 | ランチャーを選んだチャット（スマートフォン） | 従来どおり画面端にランチャーが出る。フローティングは出ない | ○ |
| 4-2 | ランチャーを選んだチャットを開く | 従来どおり**全画面**。ハンドルバーは出ない | ○ |
| 4-3 | 同上・開閉 | アニメーションせず、従来どおり即座に開閉する | ○ |
| 4-4 | この設定を持たない既存チャット | 4-1〜4-3 と同じ（ランチャー扱い） | |
| 4-5 | タブレット | フローティングを選んでいても**ランチャー**が出る | |
| 4-6 | PC | フローティングを選んでいても**ランチャー**が出る | ○ |
| 4-7 | `trigger.is_hidden` が有効 | 新旧どちらでも何も表示されない | ○ |
| 4-8 | `is_hidden` + STANDSMotion の `openWindow()` | チャットは開ける（新UI選択時はボトムシート） | ○ |
| 4-9 | ツアー・ヒント・汎用モーダルと同時表示 | チャットが前面に出る | |
| 4-10 | 管理画面のプレビュー | 従来どおり PC 向けの表示で動く | |
