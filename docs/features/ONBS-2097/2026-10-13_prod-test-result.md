# ONBS-2097 本番動作確認の結果

実施日: 2026-10-13
対象: アプリ側の変更のみ。terraform（ALBアクセスログ・WAF）は未適用。

| 項目 | 値 |

| タグ | `1.6.1`（`1.6.0` の ONBS-2097 を含む） |
| イメージタグ | `3cc8104`（1.6.1 の main マージコミット） |

### 副作用の確認

| 項目 | 結果 |

| 顧客データ | 触れていない（`chatId` が実在しないため DB 検索が空振り） |

| AI利用回数 | 加算されていない（プロダクト特定前に失敗するため顧客の枠を消費しない） |
| DB | 参照のみ（リーダー接続） |

## 結果

**dev と完全に同一の結果。** いずれも期待どおり。

### テスト1: プロトコル不一致は通知されない

`action` 欠落 / `{"action":"ping"}` / スキーマ不正 を混ぜて5回送信。
5回とも `Bad Request` が返り、5回目の応答直後に切断。

```
<切断: code=1008, reason='不正なメッセージが連続しました'>
```

**Slack 通知は切断通知の1件のみ。** 5件のエラー自体は1件も通知されなかった。

### テスト2: スキーマ通過後のエラーは最初の1件だけ通知

存在しない `chatId` で `aiChatOpenai` を6連投。
6回とも `Not Found` が返り、**Slack 通知は1件のみ**。

### テスト3: 接続単位の流量制限

同一接続で31件を連投。30件目までは `Not Found` が返り、
**31件目で `code=1008, reason='メッセージ流量の上限を超えました'` で切断**。

## ログによる裏取り

`/ecs/prod-onboarding-ai-api` の記録。

| 確認項目 | 件数 |
| --- | --- |
| `Slack notification throttled` | **35件**（テスト2の5件 + テスト3の30件） |
| `WebSocket connection closed for abuse` | 2件（理由: 不正なメッセージが連続 / 流量上限超過。いずれも送信元IP付き） |

**合計42リクエストに対し、Slack 通知は3件。** 対応前なら42件すべてが `@channel` 付きで飛んでいた。

## 補足: 1.6.0 のデプロイは一度失敗している

本リリースは `1.6.0` のデプロイが起動時の `ImportError`（greenlet 欠落）で失敗し、
`1.6.1` で修正してから本番へ反映された。顧客影響は無し。

経緯は [2026-10-13_release-incident.md](./2026-10-13_release-incident.md) に記録。
