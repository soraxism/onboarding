# クライアント管理の Dify への接続（検討メモ）

ONBS-2176（AI チャット用サーバーの外向き通信の制限）の検討中に出た論点。
**現時点では対応しない。実際にニーズが出た時点で、この案をもとに着手する。**

## 背景

Dify の接続先は、当社が管理する `dify-stands.com` / `dev.dify-stands.com` 以外に、
**クライアントが自身で管理する Dify へも接続できる設計**になる可能性がある（2026-11-02 時点では当社管理の Dify のみで利用）。

一方、2026-10-14 の不正アクセス後に入れた接続先の許可リストは、ホストを固定で持っている。

| 箇所 | 内容 |
| --- | --- |
| Onboarding-AI-API `app/core/outbound_guard.py` `DIFY_ALLOWED_HOSTS` | 送信前の確認。`https://{3ホスト}/v1/chat-messages` と完全一致のみ通す |
| onboarding-manage-api `api/rest/layers/python/lib/external_destinations.py` `DIFY_ALLOWED_HOSTS` | 保存時の確認。同じ 3 ホスト |

3 ホスト = `dify-stands.com`・`dev.dify-stands.com`・`api.dify.ai`。
**このままではクライアント管理の Dify は保存も送信もできない。**

## 要件

- クライアント管理の Dify へ接続できる
- 管理画面を乗っ取られても（10/14 はシステム管理者アカウントまで乗っ取られた）、許可していない宛先へは送られない

## 考え方

接続先を自由に登録できるようにすると、URL だけではクライアントの Dify と webhook.site を区別できない。
**「どの接続先を使ってよいか」を、管理画面から書き換えられない場所で当社が決める。**
管理画面での承認や、管理画面から書ける DB の表に許可リストを置くと、乗っ取られたときに許可リストごと書き換えられる。

## 案

1. **プロダクトごとの許可リストを SSM パラメータに置く**
   - 例: `{"<product_id>": ["https://dify.example.co.jp/v1/chat-messages"]}`
   - Terraform で管理し、変更は PR レビュー＋apply を通す（AWS の権限が無ければ変えられない）
   - プロダクト単位にするので、別のクライアントの Dify へ向け替えることもできない
2. **保存時（Manage-API）と送信前（AI-API）の確認を、同じパラメータで判定する**
   - 判定: 当社の固定 3 ホスト、または当該プロダクトに登録された URL と完全一致
   - `validate_dify_endpoint(endpoint)` → `validate_dify_endpoint(endpoint, product_id)` に変える
   - 既存の確認（https・443 番・リダイレクトを追わない・名前解決先が社内向け IP でない）はクライアントの接続先にもそのまま適用する
3. **ONBS-2176 の外向きの中継（採用する場合）の許可リストも同じパラメータから作る**
   - 正本を 1 つにして、アプリと中継の許可リストをずらさない。登録は稀なので、追加のたびに中継を配備し直す運用で足りる
4. **未登録の URL は保存時点で止める**（「この接続先は登録されていません。担当者へご連絡ください」）

### 利用開始までの流れ

1. クライアントから依頼
2. Biz がドメインの保有者がクライアントであることを確認
3. エンジニアがパラメータに追加する PR → apply
4. クライアントが管理画面で接続先を設定

クライアント側の Dify に IP 制限がある場合は、当社の送信元 IP（NAT `3.113.105.121`）を許可してもらう。中継を置いても送信元は変わらない。

## 足さないもの

要件は案 1 の許可リストで満たせるため、次は入れない。

- API キーと接続先の結び付け（接続先を変えたらキーの入れ直しを求める）
- 接続先の変更通知

クライアントが自分のプロダクトの接続先を自分の管理下の Dify に向けるのは、自分のデータを自分のサーバーへ送るだけなので問題にしない。

## ONBS-2176 への影響

外向きの中継を作る場合は、**許可リストを設定ファイルの外（パラメータ等）から読み込める形にしておく**。
固定の宛先をイメージに焼き込むと、クライアント管理の Dify を足すたびに作り直しが要る。
