# ANA 国内DP 検索結果一覧でステップの「次へ」が出ない件（2026-09-16 調査）

対象ページ: `https://www.ana.co.jp/domtour/booking/csm/search/DSCP0390/init`
（アカウント 214 / プロダクト 247 / ツアー `4ac2a12cb5…`（管理画面 ID 3452）・**旧JS 配信**）

事象: ランチャー → イントロ → ゴールを開始してもステップの「次へ」が表示されず、2 ステップ目へ進めない。
レポート上も **2026-09-10 以降、2 ステップ目へ進んだ記録が無い**。

## 結論

**ONBS-1991（イントロのチェックマークのタイミング）の改修が原因ではない。**
原因は配信 JS ではなく、**ツアーのステップ本文に埋め込まれた `<style>` が
ドキュメント全体に効いている**こと。

## 根拠

### 1. リリース前のビルドでも同じ

同じページに対し、配信中のエンジンと **リリース直前のビルド（`175dda60`＝ONBS-1991 を含まない）**
を差し替えて同じ操作をした。結果は完全に一致した。

| | 現行（6.9.0） | リリース前（`175dda60`） |
|---|---|---|
| `.g-modal-next` の有無 | あり | あり |
| computed `display` | **none** | **none** |
| インラインスタイル | 色指定のみ（display は無し） | 同左 |

### 2. 消しているのは CSS で、出どころはツアー本文

`.g-modal-next` に `display: none` を与えているのは、ページ内に注入された `<style>`。

```css
.gBtn.g-modal-next, .gBtn-manage.g-modal-next-manage {
    display: none;
}
```

この `<style>` は **ステップ本文（`steps[].content`）の中に書かれている**。
配信データを走査すると、**39 ステップ**が同じブロックを持っていた。いずれも
「ANAにキュン！告知」「特集」といった **1 ステップだけの告知系ゴール**で、
本文に独自ボタン（`.onb-custom-button`）を置き、標準の「次へ」を隠す意図のもの。

```
【国内DP】【PC/SP】【検索結果一覧】徳島で休んでく？…   (670e1cc740) step 1/1
【国内DP】【PC】【検索結果一覧】誘遊四国…              (3dc32029fc) step 1/1
【海外DP】【PC /SP】【検索結果一覧】ANAトラベラーズ…   (206d762e1e) step 1/1
…（計 39 ステップ）
```

### 3. `<style>` はドキュメント全体に効く

告知ステップが一度描画されると `<style>` が DOM に残り、**以後そのページの
すべてのステップで「次へ」が消える**。告知系ゴールは自動表示のため、
**ページを開いた直後から**この状態になっている（読み込み直後に該当 `<style>` を 1 個確認）。

そのため「フライト＋ホテル選択の基本操作」のような**複数ステップの操作ガイドが
進行不能**になる。2026-09-10 以降という時期は、告知ゴールが追加・公開された
タイミングと整合する。

## 対処案

### 案1: セレクタにスコープを付ける（実地で復旧を確認済み）

告知ステップの本文を、**そのステップのモーダルだけに効く**書き方へ変える。

```css
/* 独自ボタンを含むモーダルの中だけで標準ボタンを隠す */
.g-modal-size:has(.onb-custom-button) .gBtn.g-modal-next,
.g-modal-size:has(.onb-custom-button) .gBtn-manage.g-modal-next-manage {
    display: none;
}
```

実機で 3 通り試した結果:

| 状態 | 「次へ」の display |
|---|---|
| 現状のまま | `none`（進行不能） |
| 該当ルールを削除 | `inline-block`（進行できる） |
| 上記のスコープ版に置換 | `inline-block`（進行できる・告知側の意図も保てる） |

**39 ステップすべてに同じブロックが入っている**ため、直すときは全件が対象になる。

### 案2: ステップ設定で「次へ」を隠す

管理画面のステップ設定に「次へボタンを表示しない」相当の項目があるなら、
本文の CSS ではなくそちらを使う。本文に `<style>` を書く限り、
スコープを付けても**他ツアー・他ステップへ漏れる余地が残る**。

## 補足: 製品側で検討する余地

ステップ本文の `<style>` がガイド全体へ漏れるのは踏みやすい落とし穴なので、
本文由来の CSS をステップのモーダル配下へ自動でスコープする、
あるいは告知のような用途に「標準ボタンを隠す」設定を用意する、といった
製品側の手当ても検討する価値がある。
